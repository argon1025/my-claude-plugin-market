# 위키 개정 게이트 — 정지점을 근거 유무로 가르기

## Context

**문제**: `add`가 들이는 `확인` 출처는 doc-contract 7장상 기존 값을 교체할 수 있는 유일한 등급인데, `skills/add/SKILL.md:31`이 "답이 정본"이라 근거 없는 이견도 무조건 기존 값을 덮음. 반면 diff·sha7이라는 확정 근거를 든 `update`의 `관찰`은 기존 값을 못 덮고 `inbox.md`로 감 — 근거가 가장 약한 경로에 가장 센 권한이 붙어 있음.

**파급**: `rules/agent-guide.md:5` "사전 지식과 문서가 어긋나면 문서를 믿음"에 따라 잘못 들어간 값이 전 세션에서 모델 지식을 이기고, `update`는 `관찰` 등급이라 그 값을 고치지 못한 채 실행마다 같은 행을 `inbox.md`에 다시 쌓음.

**해결 방향**: 정지점의 기준을 "충돌인가"에서 "근거가 있는가"로 옮김. 사용자가 건네는 세 유형 중 오정보만 자기 신고가 불가능하므로, 개정·재논의·정정의 맥락이 입력에 있으면 그 설명이 문서를 이기고 멈추지 않으며, 근거 없는 이견만 질문으로 올려 답에서도 근거가 나오지 않으면 기존 값을 유지한 채 `inbox.md`로 넘김.

**수명주기**: 개정 값이 `확인 — {근거}`로 들어간 뒤 코드가 따라오면 `update` 4장의 `동일` 판정이 `verified`를 갱신하므로, 문서에 코드 미반영 표식을 두지 않아도 180일 낡음이 해소됨. 개정 이력의 정본은 git history이고 문서 본문에는 현재 값만 남김.

## 변경 1 — `rules/agent-guide.md`

매 세션 주입되는 규약이라 게이트의 전제가 여기서 서야 함. 사용자가 답한 범위(add + doc-contract) 밖이나, 5번 줄 자체가 이번 재설계의 출발점이므로 포함함.

- **5번 줄**: `문서 우선`을 무조건에서 조건부로 — 문서를 기본 정본으로 두되 사용자가 개정·재논의·정정의 맥락을 밝히면 그 설명이 문서를 이기고, 맥락 없는 이견은 문서를 이기지 못하고 10번 줄 `모순 보고`로 감
- **12번 줄**: `기록 제안`에서 `/llm-wiki:add`를 제안할 때 확정된 사실만이 아니라 그것을 정한 근거 문장을 함께 넘기도록 함
- **비포함**: 세션 기록(`feedback.md`)은 plan-workflow 소관이므로 llm-wiki 규약에서 언급하지 않음

## 변경 2 — `references/doc-contract.md`

판정 기준의 정본이므로 근거 축·출처 규격·커밋 규격을 모두 여기에 둠.

- **4장 출처 줄**: `확인`의 식별자를 "그 값을 정한 자료·판본 또는 결정"으로 규정하고(`2026-03 약관 개정`, `개인정보 처리방침 v3`), 근거를 댈 수 없는 값에만 `사용자 확인`을 남기며, 값이 무엇에서 무엇으로 바뀌었는지는 문서가 아니라 커밋 메시지에 둔다고 명시
- **7장 근거 판정 신설**: 기존 값을 덮는 사실에 `개정`(정해진 것이 바뀜)·`재논의`(다시 정함)·`정정`(처음부터 틀림) 중 하나가 입력에서 읽히면 근거 있음, 값이 맞다는 주장만 있으면 근거 없음으로 가름
- **7장 충돌 처리 개정**: 현행 "묻고 그 답이 정본"을 세 갈래로 — 근거 있는 교체는 묻지 않고 반영하며 근거를 `확인` 식별자로 기록, 근거 없는 교체는 기존 값·기존 출처·새 값을 병기해 근거를 묻고 답에서 근거가 나오면 반영·나오지 않으면 기존 값 유지 후 `inbox.md` 기재, 무인 실행은 물을 곳이 없어 항상 기재
- **7장 inbox 행 형식 이관**: `update/SKILL.md:87`에만 있어 `add`가 참조할 규격이 없던 `- [{날짜}] [{domain}] {주제} — 기존 {값} ({파일:절}, {출처}) / 새 {값} ({근거})` 행 형식을 규약으로 올림
- **8장 교체 사유**: 기존 값을 덮은 커밋은 본문에 `기존 {값} / 새 {값} — {근거}` 한 줄을 두어 개정 이력을 git history가 갖도록 함

## 변경 3 — `skills/add/SKILL.md`

절차와 정지점만 담는 현 역할을 유지하고 판정 기준은 규약을 참조함.

- **2장 근거 추출**: 사실마다 원문 위치에 더해 그 값을 정한 근거를 적고 입력에서 읽히지 않으면 `근거 없음`으로 두는 불릿 추가 — 3장 판정이 이 값으로 갈림
- **2장 dangling 해소**: 20번 줄의 미정의 용어 `개정 표기`를 `원문에 명시된 개정 일자·판본`으로 풀어 규약에 없는 문법 참조를 없앰
- **3장 교체 판정**: 충돌 중 기존 값을 덮는 건에 규약 7장 근거 판정을 적용해 갈래를 나누고, 근거 있는 건은 4장을 건너뛰어 5장으로 보냄
- **4장 질문 전환**: 근거 없는 교체 행은 값을 고르라고 묻지 않고 무엇이 그 값을 뒤집었는지를 물음
- **4장 정본 조건**: 31번 줄 "답이 정본"을 "근거가 붙은 답이 정본"으로 좁히고, `모름`·`알아서`처럼 근거가 나오지 않은 교체 행은 권장안 채택 대신 기존 값 유지 + `inbox.md` 기재로 보냄 — 위치·원문 충돌처럼 교체가 아닌 행은 현행대로 권장안 채택
- **5장 출처 줄**: `> 출처: 확인 — {그 값을 정한 자료 판본 또는 결정}, {날짜}`를 기본형으로 하고 `사용자 확인`은 근거를 댈 수 없을 때로 좁힘
- **5장 커밋**: 교체 건 커밋에 규약 8장 사유 한 줄을 담음
- **6장 보고**: `미기록`에 근거 미확보로 `inbox.md`에 남긴 행을 포함

## 특이 사항

- **스크립트 무수정**: `catalog.py`·`update.py` 어디에도 출처 줄을 파싱하는 코드가 없어 식별자 규격 변경이 기계 검사에 걸리지 않음 — 출처 줄은 순수 규약 영역
- **audit 모순 잔존**: `skills/audit/SKILL.md`의 `검증` 조치는 무승인으로 `verified`를 갱신하는데 doc-contract 4장은 "대조 없이 verified 갱신 금지"라 충돌함 — 이번 범위 밖이며 `사용자 확인` 단독 출처 문서에서 특히 위험하므로 후속 과제로 남김
- **관찰 줄 미부착**: 코드가 개정을 따라와도 `update` 4장 `동일` 판정은 본문을 고치지 않아 `관찰` 출처 줄이 얹히지 않음 — `verified`는 갱신되어 수명주기는 닫히나 코드가 동의한다는 표시는 문서에 남지 않음
- **재검증 주기**: 근거가 코드 밖에만 있는 사실은 자동 재검증 경로가 없어 180일 낡음 표시가 유일한 주기임

## 검증

문서 규약 변경이라 단위 테스트 대상이 아니며, 시나리오 리허설과 정합성 검사로 확인함.

- **시나리오 3종**: 근거 있는 개정(정지점 없이 반영·식별자에 근거), 근거 없는 이견(질문 후 근거 미확보 시 기존 값 유지·inbox 기재), 원문 내부 개정 일자 충돌(질문 없이 신구 가림)을 실제 위키에서 `/llm-wiki:add`로 각 1회 실행
- **기계 검사**: 변경 후 아래를 실행해 에러 0 확인

```
python3 llm-wiki/scripts/catalog.py --check --root ~/.ai-docs/wiki/knowledge
```

- **dangling 검사**: 규약에 정의되지 않은 용어가 스킬에 남지 않았는지 확인

```
grep -rn "개정 표기" llm-wiki/
```

- **커밋 본문 확인**: 교체가 발생한 시나리오의 커밋에서 `git log -1 --format=%B`로 `기존 / 새 — 근거` 줄이 실려 문서 본문에는 현재 값만 남았는지 대조
