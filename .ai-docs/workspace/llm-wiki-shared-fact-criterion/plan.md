# llm-wiki 담는 판정을 레포 밖 기준으로 전환 v5.3.0

## 의도

- **왜**: 규약 1장 판정이 "레포(코드·설정·테스트)를 읽은 에이전트가 같은 결론에 이르면 담지 않음"이라 출처 레포 코드만 기준이 되어, 다른 레포·에이전트(이후 추가될 레포 포함)가 알아야 하는 정책·요율·코드값이 update 5장 검토와 audit 2장 진단에서 삭제되고, 레포가 하나뿐인 초기 도메인에서는 거의 문서화되지 않음 — 2026-09-26 pigeon-trade update에서 토스증권 수수료율 3건과 지갑 체결가 규칙이 이 경로로 삭제됨
- **누가**: `/llm-wiki:update`·`/llm-wiki:audit`·`/llm-wiki:add`를 돌리는 사용자와, 세션 주입으로 위키를 읽는 각 레포 에이전트
- **완료**: `llm-wiki/references/doc-contract.md` 1·3장, update 5장, audit 2장, 주입 규약·README의 소개 문구가 아래 확정 문구로 바뀌고 llm-wiki 5.3.0으로 커밋됨

## 배경

- **판정 사용처**: 1장 판정은 update 2장 추출(sonnet, 1장 전체를 `sed`로 받음)·5장 검토(메인 상속 모델, `git grep`으로 코드 대조), audit 2장 진단(`git grep`으로 코드 대조), add 2장 제외 적용에서 읽힘 — add·update 2장은 1장 문구를 그대로 읽으므로 스킬 수정이 필요 없음
- **골든 검증(2026-09-26)**: 가상 셀러 플랫폼 도메인 25건과 레포 1개뿐인 초기 도메인 11건을 서브에이전트 블라인드 판정으로 비교함

| 기준 | 다중 레포 25건 | 초기 도메인 11건 |
|---|---|---|
| 현행 | 17/25 | 1/11 |
| 확정 문구 — 상위 모델 | 25/25 | 11/11(외부 값 괄호 조정 전 문구) |
| 확정 문구 — sonnet | 24/25, 모호 1 | 9/11, 모호 2 |

- **문구 함정**: "레포 밖이 알 필요가 없고 … 같은 결론에 이르면 담지 않음"처럼 두 조건을 한 문장에 묶으면 sonnet이 앞 조건을 건너뛰어 초기 도메인 4/11이 됨 — 확정 문구는 "레포 밖이면 담고, 레포 안이면 코드로 판정" 순서로 나눔
- **외부 값 함정**: "외부 명세 전사(소재와 함정만)"을 그대로 두면 sonnet이 수수료율을 명세 전사로 보고 제외함 — 괄호를 "소재·함정과 도메인이 쓰는 값만 담음"으로 바꿔 해결됨
- **계약 모양 함정**: 새 판정만 넣으면 호출 경로·응답 필드·이벤트 이름까지 문서로 담음 — "담지 않는 것"에 계약 모양을 명시해 해결됨
- **설정값 전사 조항**: 3장 "설정값 전사 제외"는 새 1장과 충돌해 다른 레포가 쓰는 값을 흔듦 — 레포 안에서만 쓰는 설정값은 새 1장의 코드 판정으로 제외됨(타임아웃 사례 전 실행 제외 확인)

## 확정 결정 (사용자 확인 2026-09-26)

- **판정 독자 범위**: 레포 밖 기준 — 레포 밖(이후 추가될 레포 포함)이 알아야 하면 코드에 있어도 담고, 레포 안에서만 필요하면 코드로 알 수 있을 때 제외함
- **추출 단계**: 현행 유지 — update 2장 추출도 새 1장 전체를 적용하고 추출 프롬프트는 고치지 않음
- **골든 테이블**: 이번 검증에만 사용하고 플러그인에 보관하지 않음
- **모호 사례 제외**: C22 배포 순서, S02 정책의 내부 세부 분리, S10 convention 유형 표와 코드 판정 충돌은 이번 범위에서 제외
- **소개 문구**: agent-guide·README의 "코드에 없는 사실" 표현을 새 판정과 맞게 함께 수정
- **복원 제외**: 2026-09-26 update에서 삭제된 위키 불릿 4건 복원은 이번 범위 밖

### doc-contract.md

1장 `- **판정**:` 줄 전체를 아래로 교체함.

```markdown
- **판정**: 레포 밖(다른 레포·에이전트·사람, 이후 추가될 레포 포함)이 알아야 하거나 겪는 사실은 코드에 있어도 담고, 그 레포 안에서만 필요한 사실은 그 레포의 코드·설정·테스트를 읽은 에이전트가 이 불릿 없이 같은 결론에 이르면 담지 않음 — 판정 단위는 불릿, 레포 안에서만 필요한 결정은 코드에 보이는 선택을 빼고 버린 대안·이유만 남김
```

1장 `- **담지 않는 것**:` 줄 전체를 아래로 교체함.

```markdown
- **담지 않는 것**: 지금 참이 아닌 것(변경 서사·미확정 계획), 외부 명세 전사(소재·함정과 도메인이 쓰는 값만 담음), 일반 지식, 비밀값, 레포 소관·책임·의존과 계약 모양(경로·필드·이벤트 이름) — 9·10장 그래프와 간선 너머 상대 레포 코드로
```

3장 `- **위치 판정**:` 줄에서 `— 설정값 전사 제외, 한 사실이` 를 `— 한 사실이` 로 바꿈. 이 세 곳 외 문구는 한 글자도 바꾸지 않음 — 골든 검증이 이 문구 조합으로만 수행됨.

### skills/update/SKILL.md

5장 검토 프롬프트의 `기준:` 줄에서 `1장 판정은 \`git -C {repo_path} grep {패턴} {sha}\`·\`git -C {repo_path} show {sha}:{경로}\`로 머지 시점 레포를 읽어 수행.` 을 `1장 판정의 코드 확인은 \`git -C {repo_path} grep {패턴} {sha}\`·\`git -C {repo_path} show {sha}:{경로}\`로 머지 시점 레포를 읽어 수행.` 으로 바꿈 — grep은 레포 안 사실의 확인 수단이고 삭제 여부는 1장 문장이 정함.

### skills/audit/SKILL.md

2장 진단 프롬프트의 `기준:` 줄에서 `1장 판정은 목록의 레포 줄로` 를 `1장 판정의 코드 확인은 목록의 레포 줄로` 로 바꿈. `없음` 레포의 불릿은 판정 생략 조항은 유지함.

### rules/agent-guide.md

`{WIKI_ROOT}`의 문서와 아래 레포 지도·의존은 레포 밖에 공유할 사실과 코드에 없는 사실의 정본입니다. 사용자가 세션에서 다르게 지시하면 그 지시가 우선합니다.

## 특이 사항

- **범위 밖 모호 사례**: 배포 순서처럼 CI에 흔적이 없는 절차가 확정 절차인지 계획인지, 정책 사실에서 재시도 주기 같은 레포 내부 세부를 어디까지 떼는지, convention 유형 표의 "같은 종류의 이후 작업이 따를 코드 구성 방식"과 1장 코드 판정의 충돌은 후속 과제 — 폴더 구조처럼 코드에 보이는 구성 규칙에서 sonnet 판정이 갈림
- **값 이탈 한계**: 레포 밖이 쓰는 코드 상수(수수료율 등)가 위키와 코드에 함께 있게 되어 코드만 바뀌면 위키가 낡을 수 있음 — update가 해당 머지를 `교체`(의도 인용 있음) 또는 `건너뜀`으로 보고하므로 추가 규칙은 두지 않고, 이탈이 반복되면 audit에 코드 대조 `충돌` 신호를 도입함
- **과잉 포함 위험**: "레포 밖이 알아야 하는가"를 넓게 읽으면 레포 내부 세부까지 담길 수 있음 — 골든 검증에서 재고 락·타임아웃·폴더 구조는 제외됐으나 실제 update·audit 결과로 추가 확인 필요
- **후속 작업**: 2026-09-26 pigeon-trade update에서 삭제된 불릿 4건(토스증권 국내·미국 수수료율과 KOSPI·KOSDAQ 매도 제세금, 지갑 체결가는 최신 1m 캔들 종가)은 5.3.0 반영 후 `/llm-wiki:add`로 복원
- **마켓플레이스 버전**: `.claude-plugin/marketplace.json`의 `version`(3.1.0)은 v4.0.0 이후 llm-wiki 릴리스에서 올리지 않았으므로 건드리지 않음
