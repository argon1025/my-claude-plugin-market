# codex-plan-interview-workflow 작업 기록

- `context` plan-workflow의 planning은 추정으로 요구사항의 간극을 채우지 않고 한 결정씩 인터뷰해 필요한 사항을 합의한 뒤 계획을 작성한다. 사용자는 기능별 책임 재정리와 기존 파일 안에서의 재작성을 승인했으며, 최소 코드 원칙·승인 스냅샷·계획 누적·별도 실행 세션은 유지한다.
  - source: 사용자 확인 2026-11-05
- `correction` planning의 과거 규칙은 `모르겠어요`와 `알아서 해주세요`를 함께 권장안 확정으로 처리했다. 전자는 설명·예시를 보충할 신호이고, 후자만 대상이 명확할 때 해당 항목의 위임으로 취급한다. 위임에 따른 선택은 사용자 직접 결정과 구분하며 개별 `동의`를 최종 계획·구현 승인으로 확대하지 않는다.
  - source: 사용자 확인 2026-11-05
- `why` 인터뷰의 제안·미결정 목록은 세션·플랜 모드 초안에 두고 승인된 `plan.md`에 저장하지 않는다. 최종 계획만 실행 계약으로 남기는 기존 정책을 유지하면서 별도 상태 파일·새 기록 유형·합의 판정 훅을 추가하지 않기 위함이다. 확정 결정·위임·변경 이유는 기존 feedback 유형으로 기록한다.
  - source: 사용자 확인 2026-11-05
- `constraint` planning·execute는 주입된 최근 feedback 항목만으로 최신 합의를 판정하지 않고 관련 원본 기록을 확인한다. 계획에서는 명시적 위임의 범위·제약·검증 조건을 적으며, 실행자는 누락된 요구사항을 재량으로 간주하지 않는다.
  - source: 사용자 확인 2026-11-05
- `constraint` 인터뷰 규칙 재작성의 검증은 스킬 형식·참조·JSON·셸 문법, 임시 저장소에서의 훅 실행, 답변·위임·결정 변경 사례에 대한 규칙 대조까지다. 실제 Claude 대화로 인터뷰 행동을 검증하지 않았으므로 사용자 답변에 대한 모델의 준수를 실증한 것으로 보지 않는다.
