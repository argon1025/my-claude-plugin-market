# 위키 문서 규약

위키 문서는 코드를 계획·구현·리뷰하는 에이전트가 작업 전에 읽는 현행 사실입니다. 에이전트는 세션에 주입된 `이름 — description` 목록으로 열 문서를 고르고, 목록에서 못 찾으면 본문을 grep합니다. 문서를 새로 쓰거나 고치는 모든 경로가 이 규약을 따릅니다.

## 1. 담는 사실

- **판정**: 문장마다 "이 문장이 없으면 코드를 읽은 에이전트가 계획·구현·리뷰에서 틀리는가"를 묻고, 틀리지 않으면 담지 않음 — 판정 단위는 문서가 아니라 불릿
- **레포 밖 사실**: 도메인의 다른 레포에서 작업하는 에이전트가 알아야 하는 사실(코드값의 뜻, 상태 전이, 레포 사이 의무, 한쪽이 지키지 않으면 다른 쪽이 깨지는 값)은 코드에 있어도 담음 — 그 에이전트는 이 레포 코드를 읽지 않음
- **경계 판정**: 레포 경계를 넘는 값(DB 테이블에 남는 값, API 요청·응답, 메시지, 공통코드)의 뜻과 밖에서 겪는 동작(지연·거부·중복·빈 값)은 diff에 다른 레포가 보이지 않아도 레포 밖 사실로 봄 — 그 값을 읽는 레포는 diff에 드러나지 않음
- **레포 안 사실**: 그 레포의 코드·설정·테스트를 읽으면 같은 결론에 이르는 사실은 담지 않고, 코드가 드러내지 못하는 것만 담음 — 이유, 버린 대안, 함정, 같은 종류의 이후 작업이 따를 방식

담지 않는 것은 아래와 같습니다.

- **변경 서사**: "A에서 B로 바꿈", 작업 현황, 미확정 계획 — 현재 상태 문장으로 다시 쓸 수 있으면 그 문장만 담음
- **코드 전사**: 필드 목록, 파일 위치, 호출 관계, 이름·주석 이상의 뜻이 없는 enum 선언 — 코드가 원본임, 다만 값을 쓰는 쪽이 선언을 보지 못하고 API·DB·메시지로 값만 받으면 코드값 표로 담음
- **일반 지식**: 프레임워크·표준의 문서화된 동작 — 이 도메인에서 겪은 함정이면 담음
- **외부 명세 본문**: 명세의 위치와 명세 자체의 오류·함정만 담음
- **레포 지도**: 레포의 소관과 레포 사이 의존 — `registry.json`·`deps.json` 소관
- **화면 구성**: 배치·문구·컴포넌트 구성 — 판정에 쓰이는 문구만 인용
- **비밀값**: 토큰·비밀번호·개인 정보

```
변경 서사: 취소 사유 코드를 enum에서 문자열로 바꿈
담는 문장: 취소 요청의 사유 코드(cancelReasonCd)는 문자열로 받음 — enum으로 받으면 Jackson이 미등록 값을 null로 바꿔 검증을 통과함

코드 전사: CancelReq는 orderId·cancelReasonCd·memo 필드를 가짐
작업 현황: CR 공통코드는 전 환경에 적재 완료됨
```

## 2. 위치와 이름

| 위치 | 경로 | 주입되는 세션 | 담는 사실 |
|---|---|---|---|
| 도메인 루트 | `knowledge/{domain}/{name}.md` | 도메인의 모든 레포 | 두 레포 이상에서 참이거나 다른 레포가 알아야 하는 사실 |
| 레포 폴더 | `knowledge/{domain}/{slug}/{name}.md` | 그 레포 | 그 레포 안에서만 필요한 사실 |

- **판정 대상**: 위치는 사실이 다루는 대상으로 정함 — 1장 경계 판정에 걸리는 값과 동작은 도메인 루트, 코드 구성·라이브러리 사용법·화면 구현·레포 내부 함정은 레포 폴더
- **분리**: 한 사실이 두 성격이면 둘로 나눔 — 레포 사이 의무는 도메인 루트, 그 의무를 구현하는 레포 내부의 함정은 레포 폴더
- **폴더**: 두 위치 아래에 하위 폴더를 두지 않음 — 세션 목록이 한 단계만 읽음
- **파일명**: 주제를 나타내는 2~5단어 kebab-case 명사구(영문 소문자·숫자·하이픈), 레포 폴더 문서에는 레포명을 넣지 않음

## 3. 문서 단위와 description

- **한 주제**: 업무 주제 하나가 문서 한 장이며, 규칙·코드값·함정처럼 성격이 다른 사실은 문서를 나누지 않고 4장의 절로 가름
- **description**: 요약이 아니라 "어떤 작업을 할 때 여는가" 한 문장 — "때"로 끝내고 40자 목표·60자 상한, 이 문서에만 있는 업무 낱말 1개 이상, 다른 문서와 같은 문장 금지 (`주문 취소를 요청하거나 취소 사유·이력을 다룰 때`)
- **분할**: description 한 문장이 본문을 덮지 못하면 나눔 — "관리", "처리" 같은 범주어로 올려 여러 주제를 덮지 않음
- **병합**: 같은 주제이고 항상 함께 읽히는 두 문서는 하나로 합침
- **역커버리지**: 본문이 제목·description의 범위를 덮지 못하면 제목·description을 좁힘

## 4. 문서 모양

frontmatter는 `description` 하나만 두고, 첫 줄은 `# 제목`입니다. 절은 아래 이름과 순서를 쓰고 내용이 있는 절만 둡니다.

| 절 | 담는 사실 |
|---|---|
| `## 적용 대상` | 사실이 참인 레포·모듈·채널과 제외 범위 — 도메인 루트 문서는 필수 |
| `## 규칙` | 허용·금지·판정 기준, 레포 사이 의무, 같은 종류의 이후 작업이 따를 구현 방식 |
| `## 코드값` | 코드와 뜻의 표 — 상태 코드 포함 |
| `## 상태와 전이` | 전이 조건과 전이를 일으키는 주체 — 상태 코드 자체는 `## 코드값` 표 |
| `## 절차` | 순서가 있는 단계와 실패 시 분기 |
| `## 함정` | 버그처럼 보이는 정상 동작, 코드가 막지 않는 실수, 라이브러리·인프라 함정 |
| `## 외부 참조` | 외부 명세의 `리소스`·`접근 방법`·`참조 시점` 표와 명세 자체의 오류 |
| `## 결정` | 버린 대안과 버린 이유 |

- **하위 절**: 한 절 안에서 같은 축(레포·채널·상태 묶음)의 불릿이 4개 이상이면 `###`로 묶음
- **표**: 같은 술어를 반복하는 불릿이 3개 이상이면(코드와 뜻, 조건과 결과) 표로 바꿈
- **원본 줄**: `## 코드값` 표마다 바로 위에 `` 원본: `{정의 식별자}` — 일부 ``를 두고, 근거가 정의 전체(새 enum 파일, 정의 전체가 보이는 diff 등)를 보여 준 경우만 `` 원본: `{정의 식별자}` 전 N종 ``으로 쓰며 표 행 수가 N — 에이전트가 표에 없는 값을 없는 값으로 판단해도 되는지 가름
- **집합 표기**: 닫힌 집합(enum·공통코드·상태·허용 채널처럼 원소가 정의된 값) 원소의 뜻을 말하는 사실은 개수와 무관하게 `## 코드값` 표로 씀 — 문장 속 나열은 원본 줄을 붙일 자리가 없음, 규칙 문장이 조건·결과로 인용하는 코드는 표로 옮기지 않고 5장 식별자 병기로 씀
- **뜻 미확인**: 원본 정의·주석·사용처에서 뜻을 확인하지 못한 원소는 뜻 칸을 `뜻 미확인`으로 둠 — 행을 빼면 표가 일부가 됨
- **출처**: 본문에 출처·날짜·이력을 두지 않음 — 근거는 8장 커밋 메시지에 남김

도메인 루트 문서 예시 (`knowledge/example-shop/order-cancel-reason.md`)

```markdown
---
description: 주문 취소를 요청하거나 취소 사유·이력을 다룰 때
---

# 주문 취소 사유

## 적용 대상

- 사유를 보내는 shop-admin, 검증·저장하는 shop-api, 취소 이력을 적재하는 shop-worker

## 규칙

- 주문 취소 요청(단건·일괄)의 취소 사유 코드(cancelReasonCd)는 CR 공통코드 문자열이며, shop-api가 요청 단계에서 미등록 코드를 거부함
- shop-admin은 운영자 취소 사유 코드 CR01을 항상 보냄 — shop-api는 기본값을 채우지 않아 빠지면 이력의 사유 코드가 빔
- 환불 금액은 사유 코드로 산정함 — 사유명은 운영자 언어와 입력 문구에 따라 달라짐

## 코드값

원본: 공통코드 `CR` — 일부

| 코드 | 뜻 | 환불 |
|---|---|---|
| `CR01` | 운영자 취소 | 전액 |
| `CR02` | 구매자 변심 | 배송비 차감 |

## 함정

- 결제 만료로 자동 취소된 이력은 사유명·사유 코드가 모두 비어 있는 것이 정상 — 사람이 입력하는 사유가 없는 전이임
- 일괄 취소 요청에 배송이 시작된 주문이 섞이면 배치 전체가 롤백됨(의도된 동작) — 호출 측이 취소 가능한 주문만 골라 보냄
```

레포 폴더 문서 예시 (`knowledge/example-shop/shop-worker/after-commit-listener.md`)

```markdown
---
description: 트랜잭션 커밋 후 이벤트 리스너를 추가하거나 고칠 때
---

# 커밋 후 이벤트 리스너

## 규칙

- 커밋 후 리스너(@TransactionalEventListener)는 본문 예외를 직접 잡아 오류 로그를 남김 — 스프링이 리스너 예외를 삼켜 호출부의 catch·알림 경로에 닿지 않음
- 커밋 후 리스너에서 DB를 쓰거나 이벤트를 다시 발행하면 새 트랜잭션(REQUIRES_NEW)을 엶 — 커밋 후 시점에는 쓰기 가능한 트랜잭션이 없음

## 함정

- 활성 트랜잭션 밖에서 발행한 이벤트는 커밋 후 리스너가 실행되지 않고 debug 로그만 남음 — 발행 메서드가 @Transactional 안에 있는지 확인
```

## 5. 문장

- **판정 문장**: 불릿 하나에 사실 하나를 `조건이면 결과 — 이유` 순서로 씀 — 에이전트가 코드·diff와 대조해 참과 거짓을 가를 수 있게 조건과 값을 밝힘
- **이유 꼬리**: 이유는 ` — ` 뒤에 붙이고 "~때문에 ~함" 순서로 쓰지 않음 — 이유가 있어야 에이전트가 문서에 없는 경우를 판단함, "사용자 지시"·"팀 결정" 같은 출처는 이유가 아니므로 이유를 모르면 꼬리를 두지 않음
- **식별자 병기**: 업무 낱말 뒤 괄호에 코드 식별자(클래스·필드·코드값·API 경로)를 원형으로 적고, 업무 낱말이 없으면 원형만 씀 — grep과 diff 대조의 열쇠, 파일 경로는 쓰지 않음
- **레포 주어**: 레포 사이 사실은 행위하는 레포를 주어로 씀 (`shop-admin은 CR01을 항상 보냄`)
- **의도 표시**: 이상해 보이지만 정상인 동작은 `정상`·`의도된 동작`으로 밝힘 — 리뷰 에이전트가 수정 대상으로 오인하지 않게 함
- **모호 금지**: "적절히"·"일부"·"필요시"는 조건과 수치로 바꾸고, 정해지지 않은 것은 "아직 정해지지 않음"으로 씀
- **어미**: 음·함·됨 또는 명사구로 끝냄
- **길이**: 150자를 넘으면 사실이 둘 이상인지 확인해 나눔

## 6. 겹치는 사실

- **참조 금지**: 다른 위키 문서의 링크·이름·`참고` 절을 두지 않음 — 목록이 매 세션 주입됨
- **한 곳 소유**: 같은 사실은 한 문서에만 둠 — 맞닿은 주제에는 없으면 틀리게 되는 한 문장만 문서 이름 없이 씀
- **레포 편차**: 도메인 루트 값과 다른 레포만의 사정은 도메인 루트 문서를 그대로 두고 레포 폴더 문서에 이유와 함께 씀

## 7. 고칠 때

- **근거 범위**: diff의 추가 줄과 커밋 메시지가 말하는 사실은 이 머지에서 처음 생겼는지와 무관하게 반영 대상이며, 위키에 없으면 추가함
- **집합 범위**: 코드값 표에는 근거가 보여 준 원소만 담고 원본 줄로 일부인지 밝힘 — 원본 정의를 읽어 전 원소를 채우는 완결은 문서 감사(audit) 몫
- **대조**: 사실마다 목록의 description과 `grep -ril '{핵심 식별자}' knowledge/{domain}`으로 같은 주제 문서를 찾아 넣고, 없을 때만 새 문서를 만듦
- **현재 값만**: 바뀐 값은 그 문장만 고치고, 새 값 때문에 거짓이 된 문장은 같은 편집에서 지움 — 문서 전체를 다시 쓰지 않음
- **다른 값**: 기존 문장과 값이 다르면 변경 의도를 밝힌 근거(커밋 메시지·PR 본문·작업 기록 또는 사용자 확인)가 있을 때만 고치고, 근거가 없으면 고치지 않고 두 값을 보고함
- **description**: 사실을 더할 때는 고치지 않고, 주제의 뜻이 바뀔 때만 기존 트리거 낱말을 남겨 다시 씀
- **구조 변경**: 사실을 반영하면서 문서 삭제·분할·병합·이름 변경을 함께 하지 않고 따로 제안함

## 8. 커밋

문서 한 장을 커밋 한 개로 남깁니다.

```
docs({domain}): {knowledge/{domain} 기준 상대 경로} {요약}

{근거}
기존 {값} / 새 {값}
```

- **근거**: diff 반영은 `{slug}@{sha7}`, 자료·대화 반영은 자료 이름 또는 `사용자 확인 YYYY-MM-DD`
- **교체 줄**: 기존 문장의 값을 바꾼 경우에만 둠
