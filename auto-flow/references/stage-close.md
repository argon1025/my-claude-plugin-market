# 정리 단계

개발이 끝난 이슈에서 PR의 머지와 사람의 확인을 본문에 반영하고, 모두 끝났으면 이슈를 완료로 바꾸는 단계입니다. 리뷰를 거치지 않고 바로 머지되는 PR도 있으므로, 이 단계는 리뷰나 코멘트를 보지 않고 머지와 확인만 봅니다. 코드는 고치지 않습니다.

상태가 개발완료인 이슈만 다룹니다. 다른 상태의 이슈는 고치지 않고 멈춥니다([공통 절차](common.md) 2절).

## 1. 확인

1. **PR**: "진행" 표의 PR마다 상태를 조회함([환경](environment.md) 2절). 머지됐으면 확인할 수 있는 범위에서 머지 커밋이 베이스 브랜치에 들어갔는지 봄
2. **사용자 행**: 실행한 사람이 알렸거나 직접 완료로 바꿨는지 봄
3. **사람의 확인**: 확인 방법이 `사용자:`인 완료 조건의 기록 칸에 `{이름} 확인:` 줄이 있는지 봄

## 2. 반영

| 본 것 | 하는 일 |
| --- | --- |
| PR이 머지됨 | 그 행의 상태를 머지됨으로 바꿈. 머지로 표시됐는데 베이스 브랜치에 없으면 바꾸지 않고 그 사실을 알림 |
| 사람이 확인을 적음 | 확인 방법에 적힌 확인이 모두 끝난 완료 조건의 상태를 통과로 바꿈. 확인한 내용이 조건과 다르다고 적혀 있으면 3절대로 되돌림 |
| PR이 머지 없이 닫힘 | 3절대로 되돌림 |
| 변화 없음 | 아무것도 바꾸지 않음 |

## 3. 되돌릴 때

계획을 다시 봐야 풀리는 것을 만나면 미결 사항에 행을 더해 본 것을 적은 뒤, 상태를 검토중으로 바꾸고 멈춥니다.

- PR이 머지 없이 닫힘: "그 PR을 어떻게 할지"
- 사람의 확인이 완료 조건과 다름: 무엇이 다른지와 그 기록의 위치

## 4. 끝

아래가 모두 참이면 상태를 완료로 바꿉니다.

- "진행" 표의 모든 행이 머지됨이나 완료임
- 확인 방법이 있는 모든 완료 조건이 통과임
- 미결 사항이 없음

하나라도 아니면 상태를 개발완료로 두고, 남은 것(머지를 기다리는 PR, 실행을 기다리는 사용자 행, 확인을 기다리는 완료 조건)을 알린 뒤 멈춥니다. 같은 것을 다시 요청하지 않습니다.

완료로 바꾼 뒤 호스트의 이슈 상태를 바꿀지는 [환경](environment.md) 5절을 따릅니다.
