# 수정 단계

PR에 달린 코멘트를 확인해, 변경을 요구하는 의견을 담당자로서 검토하고 반영하는 단계입니다. 리뷰 봇의 지적과 사람의 코멘트를 같은 방식으로 다룹니다. 의견을 그대로 따르지 않습니다. 이 PR이 왜 그렇게 구현됐는지를 먼저 파악한 뒤, 의견이 맞는지 코드로 확인해 받아들일지 정합니다.

이슈의 "진행" 표에서 상태가 PR 올림인 행의 열린 PR이 대상입니다. 이슈의 상태가 검토완료나 개발완료일 때만 수행하고, 검토중이면 계획이 바뀌는 중이므로 수행하지 않습니다. 머지된 PR과 닫힌 PR은 다루지 않습니다.

이 단계는 PR에서 일합니다. 수용 여부와 이유는 PR 코멘트의 답으로 남기고, 이슈 본문은 4절의 경우 말고는 고치지 않습니다([공통 절차](common.md) 2·4절).

## 1. 처리할 코멘트 고르기

PR의 코멘트를 모두 읽고([환경](environment.md) 2절) 아래는 건너뜁니다.

- `[auto-flow 수정]`으로 시작하는 코멘트. 이 단계가 남긴 답임
- 이미 `[auto-flow 수정]` 답이 달린 코멘트. 답 뒤에 같은 사람이 다시 의견을 달았으면 새 코멘트로 다룸
- 변경을 요구하지 않는 코멘트(확인, 감사, `[auto-flow 리뷰] 요약`, `[auto-flow 리뷰] 확인함`). 단순 질문에는 코드를 고치지 않고 답만 닮

처리할 코멘트가 없으면 아무것도 바꾸지 않고 멈춥니다.

## 2. 이전 맥락 파악

코멘트를 판단하기 전에 아래를 읽습니다. 구현한 대화는 볼 수 없으므로 이것이 맥락의 전부입니다.

- **이슈**: 이 PR이 구현하는 완료 조건과 그 기록 칸의 답·근거, 이 레포의 "레포별 계획"
- **PR 본문**: 작업 내역, 계획과 다르게 한 점, 영향도, 검증 결과
- **PR의 커밋과 앞선 코멘트**: 같은 의견이 앞에서 이미 다뤄졌는지, 어떤 답이 달렸는지

## 3. 수용 여부와 답

코멘트마다 현재 코드와 대조해 아래 셋 중 하나로 답합니다. 답은 그 코멘트의 답글로 달고, 답글을 달 수 없는 코멘트에는 대상 코멘트의 위치를 밝힌 새 코멘트로 답합니다.

| 답 | 하는 일 |
| --- | --- |
| `[auto-flow 수정] 고침 — {커밋}` | 의견이 맞음을 코드에서 확인한 뒤 고치고, 그 변경을 가르는 검증을 실행해 커밋함 |
| `[auto-flow 수정] 고치지 않음 — {이유}` | 코드 경로나 동작, 확정된 완료 조건을 확인한 이유를 적음. 확인하지 않고 이 답을 고르지 않음 |
| `[auto-flow 수정] 이미 고쳐짐 — {위치}` | 고쳐진 커밋이나 위치를 적음 |

- **판단 기준**: 의견이 가리키는 문제가 실제로 일어나는지 코드 경로를 따라가 확인함. 확정된 완료 조건이나 기록 칸의 답과 어긋나는 의견은 그 근거를 들어 받아들이지 않거나, 계획을 바꿔야 하면 4절대로 함. 취향이나 범위 밖의 제안은 이유를 적고 고치지 않을 수 있음
- **여러 코멘트**: 한꺼번에 모아 판단하고, 서로 부딪히는 의견은 어느 쪽을 왜 따랐는지 답에 적음
- **검증**: 고친 부분을 가르는 검증만 다시 실행함. 간단한 수정마다 전체 검증이나 리뷰를 되풀이하지 않음. 공개 시그니처나 응답처럼 밖에서 보이는 것을 바꿨으면 그 소비처의 검증도 실행함
- **게시**: 같은 브랜치에 push함. force-push는 하지 않음. 고친 내용이 PR 본문의 작업 내역이나 검증 결과를 틀리게 만들면 PR 본문도 고침. PR 본문을 고칠 도구가 없으면 달라진 점을 그 답에 함께 적음

## 4. 계획을 바꿔야 할 때

코멘트를 따르려면 완료 조건, 사람에게 물을 대상([검토](stage-plan.md) 4절), 레포 사이에 주고받는 값이 바뀌어야 하면 코드를 고치지 않습니다.

1. 이슈의 완료 조건에 미정 행을 더하고 기록 칸에 `수정 질문:`으로 코멘트의 위치, 요구하는 변경, 지금의 완료 조건과 어긋나는 점을 적음
2. 상태를 검토중으로 바꿈. 저장 직전에 본문을 다시 읽음([공통 절차](common.md) 4절)
3. 그 코멘트에 `[auto-flow 수정] 계획을 바꿔야 해서 검토로 돌림 — {완료 조건 번호}`로 답함

## 5. 끝

실행 보고에 코멘트마다의 답, 올린 커밋, 검토로 돌린 것이 있으면 그 번호를 적고 멈춥니다. 머지는 사람이 합니다.
