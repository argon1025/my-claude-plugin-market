# 이슈와 저장소 접근

## Jira

- 세션에서 사용할 수 있는 Jira 연결로 지정한 키의 최신 이슈를 조회한다. 원래 요청이 링크·첨부·댓글에 있으면 관련 자료만 읽는다. 본문은 `description`, 수정 시점은 `updated`를 확인한다. 본문 이력 링크나 수정 시점과 검토한 조건의 문구로 판본을 특정할 수 있다.
- 현재 본문에서 계획 부분만 갱신하고 원래 형식과 다른 절·표·링크를 보존한다. 형식을 보존할 수 없으면 초안을 반환한다. 판본 조건부 갱신을 지원하면 읽은 판본으로 저장한다. 충돌하면 바뀐 부분을 대조해 최신 본문에서 계획을 조정한다.
- 여러 사람이 편집하는 이슈에서 조건부 갱신 없이 본문 전체를 교체할 때는 교체 전 본문을 복구할 수 있는 변경 이력이 필요하다. 해당 이력을 조회할 수 없으면 초안을 반환한다. 저장 직전 다시 읽고, 저장 후 이력에서 **이 쓰기가 실제로 교체한 본문**과 저장 기준을 대조한다. 유실된 중간 편집은 최신 본문에 합쳐 이후 편집도 보존하고, 같은 절차로 복구 결과를 확인한다. 같은 조건을 양쪽에서 다르게 바꿨으면 두 판본과 겹친 조건을 반환해 조정한다.
- 저장 후 본문을 다시 읽어 원문과 계획을 확인하고 그 판본을 반환한다. 쓰기 응답이 끊겼다면 먼저 저장 결과를 조회한다. 전체 교체였다면 변경 이력까지 대조한 뒤 이미 반영된 계획을 중복 저장하지 않는다.
- Jira 연결이나 쓰기 권한이 없거나 사본만 제공받았다면 받은 근거로 가능한 부분을 수행한다. 사용한 사본과 반영 여부를 밝힌다. 검토만 요청받은 경우 결과를 대화로 반환한다. 검토 결과 게시까지 지정된 경우에는 해당 이슈의 댓글이나 기존 근거 링크를 사용한다.

## 저장소와 호출

- 지정된 체크아웃이나 접근 가능한 코드 호스트에서 실제 파일을 읽는다. 커밋과 경로·심볼로 근거를 식별한다. 커밋과 다른 작업 사본은 그 차이를 명시한다. 제공받은 파일 사본은 그 사본의 판본과 확인 가능한 범위를 사용한다.
- Claude Code에서는 설치된 플러그인의 `/플러그인:스킬`을, Codex에서는 스킬 선택기에 표시된 항목을 사용한다. 패키지 안의 문서는 현재 스킬 파일 기준의 상대 경로로 연다.
- 단독 호출에는 지정한 이슈와 작업 범위만 사용한다. 호출 자체로 추적 등록, 이슈 상태 전환, 재배정, 다음 단계 실행, 메시지 발송을 하지 않는다.

## 개발 작업의 판본과 인계

- 호출자가 지정한 책임만 수행한다. 새 대화에서도 Jira 키·본문 판본과 조건 번호, 저장소·코드 판본, 해당하면 PR·스레드 위치로 근거를 찾는다. 사람이 만든 계획·검증·판정도 같은 기준으로 읽는다. 이전 실행 ID나 전용 인계 파일은 필요 없다.
- 요청한 조건에 적용할 정책·계약의 출처와 판본을 대조한다. 기술 사실은 코드·계약·실행 근거를 조사한다. 결정이 필요한 경우 질문, 답할 사람과 영향받는 조건을 반환하고 독립적인 조건은 계속한다.
- 커밋은 저장소와 SHA로 특정한다. 작업 사본은 기준 SHA와 staged·unstaged 변경 및 관련 새 파일까지 포함하는 식별 가능한 차이(예를 들어 보관한 패치와 새 파일 내용의 해시)로 특정한다. PR 번호나 브랜치 이름만으로 코드 판본을 대신하지 않는다.
- 결과에 대상 위치, 조건, 확인한 계획·코드 판본, 수행한 범위와 남은 일을 남긴다. PR 게시나 스레드 회신을 맡았을 때는 요청된 목적지에만 쓴다. Jira 조건과 실행 근거의 연결까지 맡았으면 같은 판본의 링크를 해당 조건에서 찾을 수 있게 남긴다. 연결만 실패했다면 기존 결과와 링크를 조회해 빠진 연결만 보완한다.

## PR 호스트 접근과 쓰기 복구

- 세션이 제공하는 PR 연결 또는 대상 원격에 맞는 도구를 사용한다. 예를 들어 GitHub에서는 `gh`, GitLab에서는 `glab`, 그 밖의 호스트는 연결된 API를 쓸 수 있다. PR의 대상·소스 저장소와 브랜치, base·head SHA, 비교 diff, 스레드와 답글을 원본에서 확인한다. 포크 PR의 소스 원격은 대상 원격과 다를 수 있다. 사본으로 검토했으면 판본과 최신 여부를 확인한 범위를 밝힌다.
- 쓰기 직전에 대상·권한·판본을 다시 확인한다. 게시 응답이 끊기면 원격 브랜치와 PR, 리뷰, 해당 스레드의 전체 답글 또는 Jira 연결을 목적지별로 조회한다. 같은 대상·판본의 결과가 이미 있으면 그 위치를 반환한다. 누락을 확인할 수 있을 때만 남은 쓰기를 수행한다. 조회 권한·가시성 부족으로 성공 여부를 판별할 수 없으면 미확인으로 끝낸다.
