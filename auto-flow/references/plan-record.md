# 계획과 검토 결과

이슈 본문에 저장소 전체를 아우르는 현재 계획 하나를 둔다. 이슈 키·링크와 본문 판본을 기준으로 조건을 식별한다. 기존 조건 번호나 짧은 조건명을 그대로 사용한다. 같은 조건에 연결된 코드·정책·검토 링크가 있으면 다시 활용한다. 이전 대화나 특정 스킬의 출력 양식을 시작 조건으로 삼지 않는다.

## 이슈 본문의 계획

원래 요청과 그 출처를 보존한다. 계획에는 목표와 요청의 종료 지점, 적용 정책과 결정 출처, 적용 대상을 적는다. 각 조건은 다음 질문에 답할 수 있게 쓴다.

- 어느 대상에서 어떤 입력이나 행동이 어떤 결과를 내야 하는가? 산출물이 목표라면 어느 산출물이 어떤 검토를 거쳐야 하는가?
- 어느 저장소가 실행과 검증을 맡고, 다른 저장소의 어떤 계약이나 작업을 기다리는가?
- 무엇을 어떻게 관찰하면 통과와 실패를 구별할 수 있는가? 특정 환경이 조건이면 그 환경을 적는다. 실행 후 증거를 찾을 수 있도록 해당 조건에 연결한다.

질문이 남으면 답할 곳·출처와 영향을 받는 조건을 연결한다. 답이 오면 해당 결정과 이유, 달라진 범위를 같은 계획에 반영한다. 정책 문서와 현재 코드가 다를 때에는 양쪽의 적용 범위와 판본을 확인한다.

## 영역 검토 결과

이슈·계획 판본, 조건, 저장소·코드 판본과 경로를 짝지어 돌려준다. 각 조건에 대해 확인한 현재 동작, 실행 가능한 변경 또는 충돌, 영향을 받는 소비자와 검증 방법을 적는다. 미확인 사항은 필요한 근거와 답할 곳을 적는다. 다음 작업에서 해당 경로를 바로 찾을 수 있을 만큼 구체적으로 남긴다.

## 독립 검증 결과

이슈·계획 판본과 원래 목표를 기준으로 **조건 → 예정한 검증 근거 → 착수 가능 또는 보완 필요와 이유**를 남긴다. 빠진 목표나 차단 사유가 있으면 무엇을 보완하면 판단이 달라지는지와 영향 범위를 적는다. 독립적으로 착수할 수 있는 작업을 함께 밝힌다.

검토 결과는 호출자에게 반환한다. 이슈에 연결하도록 요청받으면 해당 조건에서 찾을 수 있는 판본과 근거 링크를 사용한다. 같은 근거를 가리키는 결과는 중복 등록하지 않는다.
