# 계획과 검토 결과

이슈 본문에 저장소 전체를 아우르는 현재 계획 하나를 둔다. 이슈 키·링크와 본문 판본을 기준으로 조건을 식별한다. 기존 조건 번호나 짧은 조건명을 그대로 사용한다. 같은 조건에 연결된 코드·정책·검토 링크가 있으면 다시 활용한다. 이전 대화나 특정 스킬의 출력 양식을 시작 조건으로 삼지 않는다.

## 정책 판본 확인

단계를 시작하거나 재개할 때 계획이 인용한 정책을 열어 이번 대상에 유효한 판본·적용 범위와 대조한다. 보장할 동작이 바뀌었다면 Jira나 코드가 그대로여도 영향을 받는 조건과 의존 작업만 보류한다. 계획 조정과 해당 영역·독립 재검증에 쓸 결정 출처, 달라진 조건, 기존 근거가 유효한 범위를 반환한다. 문구만 달라졌으면 판정을 유지한다. 사본만 읽을 수 있으면 검토한 판본과 현행 여부를 확인하지 못한 범위를 밝힌다.

## 이슈 본문의 계획

신규 계획, 기존 계획 조정, 미반영 초안에 같은 틀을 쓴다. 기존 계획은 같은 자리에서 갱신한다. 요청 원문, 다른 절과 그 안의 표·첨부·링크를 보존한다. 조건은 위치나 순서가 바뀌어도 기존 번호를 유지하고 새 조건에만 사용하지 않은 번호를 붙인다. 본문 형식이 다르면 해당 형식의 제목·표·링크로 표현한다.

```markdown
## 계획

**목표와 종료 지점** — [원래 요청 위치], [누구에게 어떤 결과를 어디까지 전달하는가]

**적용 정책·계약** — [규격·결정의 출처와 판본], [적용 대상과 예외]

| 완료 조건 | 대상과 입력·행동 | 기대 결과와 그 근거 | 검증 방법·필요 환경 | 구현 담당 레포 / 검증 담당 | 기다리는 계약·작업 |
| --- | --- | --- | --- | --- | --- |
| [조건 번호·이름] | [대상에서 할 일] | [관찰할 결과와 이를 보장하는 요청·결정] | [성공과 실패를 가를 관찰] | [담당] | [선행 조건] |

**미결 질문** — [질문 / 답할 사람·출처 / 답을 기다리는 조건]

**결정과 변경 이유** — [선택과 이유 / 출처·판본 / 영향을 받는 조건·재검토 범위]

**검토·검증 근거** — [조건 / 계획·변경 판본 / 검토·실행 결과와 링크]
```

각 행에는 해당 입력의 기대 결과를 보장하는 출처와 성공·실패를 가릴 방법을 적는다. 실행 전에는 수집할 근거를 적고 실제 결과 링크는 확보한 뒤 연결한다. 미결 질문이나 후속 결정이 없으면 해당 항목은 생략할 수 있다. 조정 시 유효한 검토 링크와 조건별 판본을 유지한다.

## 영역 검토 결과

이슈·계획 판본, 조건, 저장소·코드 판본과 경로를 짝지어 돌려준다. 각 조건에 대해 확인한 현재 동작, 실행 가능한 변경 또는 충돌, 영향을 받는 소비자와 검증 방법을 적는다. 미확인 사항은 필요한 근거와 답할 곳을 적는다. 다음 작업에서 해당 경로를 바로 찾을 수 있을 만큼 구체적으로 남긴다.

## 독립 검증 결과

이슈·계획 판본과 원래 목표를 기준으로 **조건 → 예정한 검증 근거 → 착수 가능 또는 보완 필요와 이유**를 남긴다. 빠진 목표나 차단 사유가 있으면 무엇을 보완하면 판단이 달라지는지와 영향 범위를 적는다. 독립적으로 착수할 수 있는 작업을 함께 밝힌다.

검토 결과는 호출자에게 반환한다. 이슈에 연결하도록 요청받으면 해당 조건에서 찾을 수 있는 판본과 근거 링크를 사용한다. 같은 근거를 가리키는 결과는 중복 등록하지 않는다.
