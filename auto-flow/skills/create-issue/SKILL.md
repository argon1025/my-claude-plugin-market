---
name: create-issue
description: Use when asked to register a request as a new issue for this plugin's loop ("이슈 만들어줘", "이 요청 이슈로 등록해줘", "일감 생성해줘"), or when a bot takes a request on someone's behalf — checks that the request states a desired outcome, searches for an open issue with the same request, then creates the issue with the template applied, the request section filled and missing defect details recorded as open questions, and stops. Returns questions instead of creating when the desired outcome is unclear. NOT for writing acceptance criteria or plans (plan-issue).
---

요청 하나를 루프가 바로 다룰 수 있는 이슈로 만들고 멈춥니다. 계획은 세우지 않고 검토도 시작하지 않습니다.

1. **받는 것**: 요청 원문과 만들 곳을 확인합니다. 원문은 붙여 넣은 글이나 대화이고, 위치로만 받았으면 [환경](../../references/environment.md) 3절대로 읽습니다. 만들 곳은 호출할 때 받은 값, 실행자의 지침, 환경 1절 순으로 찾고 어디에도 없으면 묻습니다. 이슈를 만들 도구가 없으면 시작하지 않고 그 사실을 알립니다.
2. **원하는 결과**: 요청에서 무엇이 달라지기를 원하는지 찾습니다. 찾을 수 없으면 만들지 않고, 요청자에게 물을 질문을 알린 뒤 멈춥니다. 원하는 결과는 분명한데 세부 정책이나 값이 비어 있으면 채우지 않고 그대로 만듭니다. 빈 부분은 검토 단계가 미결 사항으로 다룹니다.
3. **중복 확인**: 같은 요청의 열린 이슈를 검색합니다. 대상과 원하는 결과가 같은 이슈가 있으면 만들지 않고 그 이슈를 알린 뒤 멈춥니다.
4. **관계자**: 환경 4절이 정한 곳에서 요청자, 결정할 사람, 대상 서비스의 담당을 찾습니다. 정한 곳이 없으면 요청 원문에 드러난 사람만 적습니다. 찾지 못한 역할은 "미정"으로 두고, 커밋 이력이나 과거 이슈의 담당자로 추정하지 않습니다.
5. **결함 제보의 빠진 정보**: 요청이 결함 제보면 관찰한 현상, 기대한 결과, 발생한 환경과 조건(어느 환경에서, 어떤 계정이나 데이터로, 언제)이 원문에 있는지 봅니다. 빠진 것은 지어내지 않고 "미결 사항"에 질문으로 적습니다. 답할 사람은 요청자로 두고, 막힌 것에는 "생성 시 확인"이라고 적습니다. 이 질문을 실제로 물을지는 검토 단계가 정하므로 여기서는 확인을 요청하지 않습니다.
6. **만들기**: [이슈 템플릿](../../references/issue-template.md)의 열 절로 본문을 쓰고 "요청" 절, 5번의 질문, "이력"의 첫 줄만 채웁니다. 나머지 절은 템플릿 그대로 둡니다. 제목은 원하는 결과를 한 줄로 쓰고, 프로젝트에 제목 관례가 있으면 따릅니다. `auto-flow` 라벨을 붙이고 상태는 검토로 둡니다.
7. **원문 남기기**: 원문을 다시 볼 곳이 없으면(위치 없이 붙여 넣은 요청) 원문을 `[auto-flow] 요청 원문`으로 시작하는 댓글로 남기고 "요청이 온 곳"에 그 댓글의 위치를 적습니다.
8. **확인**: 만든 이슈를 다시 읽어 본문과 라벨이 들어갔는지 확인합니다. 응답이 끊겨 만들어졌는지 알 수 없으면 다시 만들기 전에 3번의 검색으로 확인합니다.
9. **알림**: 이슈의 키와 위치, 관계자 가운데 "미정"으로 남은 역할, 미결 사항에 적은 질문을 알리고 멈춥니다.

"요청" 절에는 요청에 있는 것만 적습니다.

- **원하는 결과**: 요청자의 말에서 옮겨 번호를 붙여 한 줄에 하나씩 적음. 값, 문구, 식별자, 오류 메시지는 요청에 적힌 그대로 옮기고, 요청에 없는 내용을 관행이나 추측으로 채우지 않음
- **하지 않을 것, 기한**: 요청자가 적었을 때만 적음
- **원인과 해결 방법**: 요청자가 적었으면 "요청자가 본 원인과 해결 방법"에 적고 "원하는 결과"로 옮기지 않음
- **원문**: 본문에 붙이지 않음. 링크와 첨부는 "참고 자료"에 적음
- **쓰지 않는 것**: 완료 조건, 결정, 레포별 계획은 쓰지 않음. 검토 단계가 씀

이 요청이 이슈로 만들 요청인지 가르는 일과 요청자에게 결과를 알리는 일은 이 스킬이 하지 않고 호출한 쪽이 합니다.
