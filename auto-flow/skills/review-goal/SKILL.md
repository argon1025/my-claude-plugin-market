name: review-goal
description: 지정한 Jira 계획 판본의 완료 조건을 이미 수집된 산출물·실행 증거로 독립 판정하고 증거 수집 또는 결함 조사·수정 담당에게 인계한다.
---

계획 판본, 조건별 입력·기대 결과·종료 지점과 제공된 근거를 읽는다. 사람이나 다른 담당자가 수집한 근거도 같은 기준으로 사용한다. 실행을 다시 하거나 수정을 시작하지 않는다.

| 조건별 판정 | 대조할 근거와 인계 |
| --- | --- |
| 충족 | 조건이 요구하는 진입점·환경·판본에서 기대한 결과를 직접 입증하는 근거 위치를 연결한다. SQL 작성·검토가 목표면 같은 판본의 SQL과 검토 결과로 판정할 수 있다. |
| 근거 부족 | 관찰된 부분과 빠진 부분을 명시한다. 실행 담당에게 해당 조건, 필요한 환경·판본, 다시 들어갈 진입점과 수집할 관찰을 넘긴다. 화면 연동 조건에는 같은 실행의 실응답과 화면 관찰이 필요하다. 별도 실행의 API 응답과 목업 화면을 합치지 않는다. |
| 실제 동작 미충족 | 해당 조건의 입력을 실행해 관찰한 값과 그 입력에 확정된 기대값을 짝지어 차이를 밝힌다. 원인이 불명확하면 조사 담당에게 증상·입력·판본·로그를, 원인 경로가 확인됐으면 해당 레포 담당에게 수정 범위를 넘긴다. 수정 뒤 같은 입력·경로를 다시 실행할 조건을 표시한다. |

조건마다 표의 판정 하나와 그 이유를 적는다. 코드 리뷰에서 확인한 미구현은 수정 담당에게 넘긴다. 실행이 필요한 조건에서 중간 단계까지만 관찰했으면, 그 단계의 값 자체가 계획에서 보장한 값인지 확인한다. 다른 구성 요소의 계약이나 리뷰어의 수정 제안을 그 단계의 기대값으로 쓰면 오판할 수 있다. 일부에서 실제 차이가 관찰되면 실패한 입력과 증거가 없는 나머지 경로를 구분한다. 기대값이 미결이면 필요한 결정을 인계한다.

판정에는 계획 판본과 조건 번호를 유지한다. 코드·정책·계획이 바뀌면 기존 증거가 새 조건을 여전히 입증하는지 확인한다. 영향을 받았거나 영향이 불명확한 조건만 새 증거를 요청하고, 유지한 결과에는 이유를 적는다. 배포 여부나 Jira 상태 전환은 해당 책임을 맡은 담당자가 판단한다.
