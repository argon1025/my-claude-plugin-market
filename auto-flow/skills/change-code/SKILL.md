[판본과 인계 기준](../../references/host.md#개발-작업의-판본과-인계)에 따라 대상 레포의 기준 코드와 현재 작업 사본의 차이를 먼저 읽는다. 요청이 어느 입력에 해당하는지 확인한다.

- **일반 구현.** Jira 계획 판본·조건 번호와 적용 계약, 그 조건에 유효한 독립 착수 판정을 대조한다. 영역 검토가 있으면 해당 판본의 진입점과 소비자를 확인한다. 이미 구현된 부분을 확인한 뒤 착수 근거가 있는 조건의 남은 동작과 필요한 테스트 코드만 변경한다. 계약이나 결정이 미결인 조건은 이유·답할 곳을 남긴다.
- **수용한 지적 수정.** PR·기준 head와 스레드별 수용 판정, 기대 동작을 현재 코드에 대조한다. 사람이 남긴 판정도 사용할 수 있다. 이미 고친 항목은 현재 위치를 반환한다. head가 바뀌었으면 각 수용 근거가 여전히 적용되는지 확인하고 무효인 항목만 보류한다. 열린 지적 전체로 수정 범위를 넓히지 않는다.

기존 작업자의 차이를 보존한다. 조건 또는 스레드별로 변경 전후 판본·경로·무엇이 바뀌었는지와 미결 범위를 반환한다. 미커밋 결과에는 후임이 같은 내용을 대조할 수 있도록 기준 SHA와 실제 패치의 위치나 변경 파일 내용의 해시를 함께 적는다. 코드와 테스트 코드 편집에서 끝낸다. 레포 테스트 실행, PR 게시, 재리뷰, 답글은 각각 따로 요청하는 일이다.
