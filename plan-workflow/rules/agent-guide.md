# 작업 기록 규약 (세션 전체 적용)

작업 중 확인한 의도와 알게 된 사실을 `{WORKSPACE_ROOT}/{slug}/`에 남깁니다. 스킬을 부르지 않아도 적용되며, 사용자가 세션에서 다르게 지시하면 그 지시가 우선합니다.

- **파일**: `feedback.md`는 항상, `plan.md`는 플랜 모드를 거친 경우에만 두며, 없는 폴더는 기록 시점에 만들고 머지 뒤에도 지우지 않음
- **의도 확인**: 코드를 고치기 전에 왜·누가·완료 조건을 확인함. 코드·문서의 현재 상태와 사용자가 원하는 결과를 구분하고, 이미 명시한 요구는 재질문하지 않으며 모르는 요구사항은 추정 대신 물음. 확인된 의도는 `context` 항목으로 기록함
- **계획**: 요구가 불분명하거나 규모 있는 작업은 플랜 모드에서 `{PLUGIN_NAME}`의 planning 스킬을 로드해 한 결정씩 인터뷰하고 합의를 완료함. 최종 승인된 계획만 `plan.md`로 커밋하며 기존 계획에는 절을 덧붙임. 개별 답변의 동의는 최종 계획·구현 승인이 아니며, 구현은 새 세션의 `{PLUGIN_NAME}`의 execute 스킬로 시작함
- **기록 기준**: 코드를 읽은 에이전트라도 이 문장이 없으면 잘못 움직일 사실만 드러나는 즉시 `feedback.md` 끝에 덧붙임 — `why`(선택 근거·트레이드오프), `correction`(틀린 것으로 드러난 가정과 바로잡은 사실), `constraint`(코드가 드러내지 못하는 업무·인프라 규칙, 라이브러리 함정), `context`(확인된 의도, 합의한 범위, 후속 작업, 의도적 단순화의 한계)
- **제외**: 파일 하나만 봐도 아는 사실, 이번 응답에만 해당하는 일시적 진행 지시, "A에서 B로 바꿈" 같은 변경 서사
- **형식**: 첫 기록 전에 `{PLUGIN_ROOT}/references/record-format.md`를 읽음
