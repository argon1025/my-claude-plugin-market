# 작업 기록 규약 (세션 전체 적용)

작업 중 확인한 의도와 알게 된 사실을 `.ai-docs/workspace/{slug}/`에 남깁니다. 스킬을 부르지 않아도 적용되며, 사용자가 세션에서 다르게 지시하면 그 지시가 우선합니다.

- **파일**: `feedback.md`는 항상, `plan.md`는 플랜 모드를 거친 경우에만 두며, 없는 폴더는 기록 시점에 만들고 머지 뒤에도 지우지 않음
- **의도 확인**: 코드를 고치기 전에 왜(오늘 무엇이 부족한지)·누가 겪는지·무엇이 참이 되면 끝인지를 확인하고, 요청·코드로 확정되지 않는 항목은 추론 대신 사용자에게 물음. 확인된 의도는 사용자 문장 그대로 `context` 항목으로 기록함
- **계획**: 요구가 불분명하거나 규모 있는 작업은 플랜 모드에서 `/plan-workflow:planning`을 로드함. 승인된 계획은 `plan.md`로 커밋하고 구현은 새 세션에서 `/plan-workflow:execute`로 시작함
- **기록 기준**: 코드를 읽은 에이전트라도 이 문장이 없으면 잘못 움직일 사실만 드러나는 즉시 `feedback.md` 끝에 덧붙임 — `why`(선택 근거·트레이드오프), `correction`(틀린 것으로 드러난 가정과 바로잡은 사실), `constraint`(코드가 드러내지 못하는 업무·인프라 규칙, 라이브러리 함정), `context`(확인된 의도, 합의한 범위, 후속 작업, 의도적 단순화의 한계)
- **제외**: 파일 하나만 봐도 아는 사실, 이번 작업에만 해당하는 지시, "A에서 B로 바꿈" 같은 변경 서사
- **형식**: 첫 기록 전에 `{PLUGIN_ROOT}/references/record-format.md`를 읽음
