# plan-workflow

이슈를 한 결정씩 합의해 계획하고, 승인된 계획대로 실행하는 플러그인입니다. 이슈 여러 개를 한 번에 받을 수 있고, 계획에는 사용자가 확인한 내용만 들어갑니다. 계획과 이후에도 쓸 지식은 `.ai-docs/workspace/{이슈 키}/`(상위 경로는 `config.json`의 `workspace.root`)에 남깁니다.

| 스킬 | 트리거 예 | 역할 |
| --- | --- | --- |
| `/plan-workflow:planning` | "계획 세워줘", "요구사항 인터뷰", "기능 설계", "이슈 여러 개 같이 진행" | 이슈 분류 → 근거 확인 → 한 결정씩 합의 → 이슈별 계획 승인 → 같은 세션에서 실행으로 이어 감 |
| `/plan-workflow:execute` | "계획 실행", "플랜 실행" | 승인된 계획을 읽고 합의 단위 → 검증 → 커밋으로 실행. 계획에 없는 결정은 멈춰서 묻고 바뀐 합의는 계획을 고쳐 씀 |

## 설치

```
/plugin marketplace add argon1025/my-claude-plugin-market
/plugin install plan-workflow@my-claude-plugin-market
```

요구 사항은 `python3`와 `git`입니다. git 저장소 밖에서는 아무것도 주입하지 않습니다.

## 진행 순서

1. **분류**: 요청에 담긴 이슈를 대상 레포, 관계(독립, 선행 관계, 공통 결정), 순서 표로 정리함. 이슈가 하나여도 같은 절차를 따름
2. **근거 확인**: 이슈 본문·문서·앞선 기록의 주장을 코드와 대조하고, 결과를 출처와 함께 계획의 `확인한 사실`에 적음
3. **합의**: 이슈 하나씩, 결정 하나씩 묻고 합의될 때마다 계획에 적음. 질문과 설명은 `references/question-guide.md`를 따름
4. **계획 승인**: 이슈마다 합의 단위 목록과 `plan.md` 경로를 보이고 승인받음. 계획에 처음 나오는 내용은 없음
5. **실행**: 승인된 이슈를 같은 세션에서 실행함. "계획까지만"이라고 하면 승인 뒤 멈추고, 새 세션에서 execute로 이어 갈 수 있음

- **여러 이슈의 순서**: 독립이면 합의는 순차로, 실행은 병행함. 선행 관계면 앞 이슈의 결과물이 생긴 뒤 뒤 이슈를 실행함. 공통 결정이면 그 결정을 가진 이슈를 먼저 구현해 확인받은 뒤 나머지 이슈의 합의를 시작함
- **플랜 모드**: 쓰지 않음. 합의를 파일에 바로 적어야 하고 승인을 이슈마다 받기 때문이며, 승인 전 코드 수정 금지는 스킬 규칙으로 지킴
- **요청 우선**: 검토만 요청받으면 파일·커밋을 만들지 않으며, 사용자가 정한 범위와 지시가 이 절차보다 우선함

## 산출물

```
.ai-docs/workspace/
└── {이슈 키}/
    ├── plan.md        # 이 이슈에서 하기로 한 것: 의도, 확인한 사실, 합의, 연결, 검증, 범위 밖
    └── feedback.md    # 이슈가 끝난 뒤에도 쓸 지식: constraint, correction, why
```

- **폴더 이름**: 이슈 키이며, 이슈 키가 없는 작업은 주제의 kebab-case 이름을 씀. 같은 키의 폴더가 있으면 이어 씀
- **여러 레포**: 코드가 바뀌는 레포마다 기록을 두고, 겹치는 내용은 한 곳에만 쓴 뒤 나머지가 가리킴
- **현재 상태만**: 두 파일은 지금 유효한 내용만 담음. 합의가 바뀌면 해당 부분을 고쳐 쓰고 이력은 git에 맡김
- **형식 문서**: 위치와 `feedback.md`는 `references/record-format.md`, `plan.md`는 `references/plan-format.md`

## 동작 방식

- **SessionStart**: `rules/agent-guide.md`의 규약 요약과 `## 현재 워크스페이스` 블록을 주입하며, matcher가 없어 startup·resume·clear·compact 모두에서 다시 실행됨
- **기록 위치 안내**: 브랜치명에서 대문자 이슈 키(`PROJ-123`)를 뽑아 그 키가 들어간 폴더와 기록 파일 유무를 알리고, 파일이 있으면 작업 전에 읽으라고 지시함. 기록 본문은 주입하지 않음
- **키 없는 브랜치**: 폴더를 정하지 않고, 요청의 이슈 키나 작업 주제로 정하도록 안내함

규약 준수 여부는 검사하지 않습니다. 끄려면 `/plugin`에서 플러그인을 비활성화합니다.

## 설정

| 키 | 기본값 | 의미 |
| --- | --- | --- |
| `workspace.root` | `.ai-docs/workspace` | 기록 폴더의 상위 경로(저장소 루트 기준), 규약과 워크스페이스 블록의 경로가 이 값으로 치환됨 |

## 방법론 출처

더 적은 코드로 되는 방법을 순서대로 확인하는 원칙은 [ponytail](https://github.com/DietrichGebert/ponytail)의 단계별 최소 구현 원칙을 계획 단계의 대안 검토로 옮긴 것입니다.

## Codex 지원

[마켓플레이스 설치·검증 안내](../README.md#codex-설치)를 따릅니다. 공통 스킬과 규약을 사용하며, Codex의 $ 선택기에서 이 플러그인의 스킬을 선택합니다. 번들 훅이 있는 플러그인은 /hooks에서 검토·신뢰해야 세션 주입이 실행됩니다.

계획 승인은 planning의 승인 질문에 사용자가 답한 것만 뜻하며, 계획 도구 호출이나 계획 모드 전환을 승인으로 해석하지 않습니다. 쓰기가 막힌 모드에서는 분류표까지만 보이고 쓰기 가능한 모드로 바뀔 때까지 기다립니다.
