# plan-workflow

요구사항을 한 결정씩 인터뷰해 합의한 뒤 계획을 작성하고, 구현은 별도 세션에서 진행하는 플러그인입니다. 계획 스냅샷과 결정·제약을 `.ai-docs/workspace/{slug}/`(상위 경로는 `config.json`의 `workspace.root`)에 남깁니다.

| 스킬 | 트리거 예 | 역할 |
| --- | --- | --- |
| `/plan-workflow:planning` | "계획 세워줘", "요구사항 인터뷰", "플랜 모드", "기능 설계" | 현황·의도 확인 → 항목별 인터뷰 → 합의 완료 확인 → 계획 작성 → 최종 승인 후 스냅샷 커밋·인계. 기존 계획에는 `## 추가 계획` 절을 덧붙임 |
| `/plan-workflow:execute` | "계획 실행", "플랜 실행" | 새 세션에서 승인 계획·관련 원본 기록을 읽고 태스크 → 검증 → 커밋으로 실행. 위임 범위 밖의 결정은 인터뷰 후 `## Re-plan` |

## 설치

```
/plugin marketplace add argon1025/my-claude-plugin-market
/plugin install plan-workflow@my-claude-plugin-market
```

요구 사항은 `python3`와 `git`입니다. git 저장소 밖에서는 아무것도 주입하지 않습니다.

## 인터뷰와 승인

한 번에 하나의 결정만 질문합니다. 현재 상태·실제 동작 예시·대안·추천 근거를 설명하고, 답변에 따라 합의와 다음 질문을 갱신합니다. 구조·계약을 결정할 때는 변경 위치와 결과 형태도 보여줍니다.

- **답변 해석**: `동의`는 직전 결정에만 적용하며, `모르겠다`는 설명을 보충할 신호임. `알아서 결정해`는 해당 항목의 명시적 위임으로 기록하고 범위 안에서 판단함
- **합의 추적**: 확정·제안·미결정·위임·철회를 구분하고, 결정이 바뀌면 영향을 받는 계약·정책·검증도 다시 확인함. 코드의 현재 동작은 사용자 요구사항을 대신하지 않음
- **계획 전환**: 필요한 결정이 합의되거나 위임되고 모순·누락이 해소되면 최종 합의 요약을 확인받고 계획을 작성함. 작성 중 새 결정이 발견되면 인터뷰로 돌아감
- **승인 경계**: 개별 동의·합의 요약 확인·최종 계획 승인을 구분함. 최종 계획 승인 후에만 `plan.md`·`feedback.md`를 커밋하고 새 세션의 execute를 안내함. 계획 승인만으로 구현하지 않음
- **요청 우선**: 검토만 요청받으면 파일·커밋을 만들지 않으며, 사용자가 별도로 정한 기록·커밋·실행 범위는 그 지시를 따름

## 동작 방식

- **SessionStart**: `rules/agent-guide.md`와 `## 현재 워크스페이스` 블록을 주입하며, matcher가 없어 startup·resume·clear·compact 모두에서 다시 실행됨
- **slug 계산**: 현재 브랜치명의 `/`를 `-`로 바꾼 값을 훅이 계산해 값으로 주입하며, `main`·`master`·`develop`이나 detached HEAD면 미확정으로 표시해 첫 기록 시 이슈 키 또는 작업 주제로 폴더를 정하게 함
- **기록 자동 로드**: 현재 slug 폴더의 `feedback.md`를 주입하되 4,000바이트 초과 시 최근 항목만 포함함. planning·execute는 관련 원본 기록도 읽어 최신 합의를 확인함. `plan.md`가 있으면 실행·추가 계획 스킬을 안내함
- **PostToolUse(ExitPlanMode)**: 최종 계획 승인 시 핸드오프 규칙을 다시 주입해 기본적으로 스냅샷 커밋과 execute 안내에서 끝나게 함. 상세 인터뷰·승인 규칙은 planning이 소유하며 훅이 합의 여부를 판정하지 않음
- **사전 정보 활용**: planning은 질문 전에 세션에 주입된 사전 정보(위키·문서 목록·작업 기록)와 코드를 먼저 확인하고 확인한 문서를 `## 선행 읽기`에 적어, execute가 새 세션에서 코드보다 먼저 읽게 함
- **형식 지연 로드**: `feedback.md` 항목 형식은 `references/record-format.md`에, `plan.md` 필수·선택 절과 순서는 `references/plan-format.md`에 두고 각각 첫 기록 전·계획 최종화 전에 읽게 하여 상시 주입에서 제외함

규약 준수 여부는 검사하지 않습니다. 끄려면 `/plugin`에서 플러그인을 비활성화합니다.

## 설정

| 키 | 기본값 | 의미 |
| --- | --- | --- |
| `workspace.root` | `.ai-docs/workspace` | 기록 폴더의 상위 경로(저장소 루트 기준), 규약·워크스페이스 블록의 경로가 이 값으로 치환됨 |

## 산출물

```
.ai-docs/workspace/
└── {slug}/
    ├── plan.md        # 최종 승인된 계획 원문 + `## 추가 계획`·`## Re-plan` 절
    └── feedback.md    # 항상, 유형 코드 불릿(why·correction·constraint·context)
```

## 기록 규약 요약

- **의도 확인**: 코드를 고치기 전에 왜·누가·완료 조건을 파악하고 이미 명시한 내용은 재질문하지 않으며, 확인된 의도를 `context` 항목으로 기록
- **기록 기준**: 코드를 읽은 에이전트라도 없으면 잘못 움직일 사실만 `why`·`correction`·`constraint`·`context` 네 유형으로 기록
- **계획 분리**: 계획 세션은 `plan.md`·`feedback.md` 스냅샷 커밋에서 끝나고 구현은 새 세션에서 시작
- **계획 누적**: 같은 slug에 계획이 이미 있으면 덮어쓰지 않고 `## 추가 계획 YYYY-MM-DD — {계기}` 절로 덧붙이며, 무효가 된 앞 절은 삭제 대신 폐기 선언으로 표시
- **덧붙이기**: 앞선 항목은 고치지 않고 파일 끝에 추가하며 PR 전 브랜치를 한 번 훑어 보충
- **기록 용도**: `feedback.md`는 이후 작업이 앞선 결정·제약을 확인하는 기록이자, 암묵지를 위키 같은 팀 문서로 옮길 때의 원천
- **판단 근거**: 위임 범위는 `context`, 위임에 따른 선택은 `why`, 결정 변경·철회는 `correction`에 남기며 제안·미결정을 확정 사실로 기록하지 않음
