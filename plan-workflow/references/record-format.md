# feedback.md 기록 형식

`.ai-docs/workspace/{slug}/feedback.md`의 항목 형식과 갱신 규칙입니다. 유형 정의와 기록 기준은 세션에 주입된 작업 기록 규약을 따릅니다.

## 항목 형식

- **구조**: 제목 한 줄 뒤에 최상위 `- ` 불릿만 두고, 불릿 하나가 사실 하나이며 첫 토큰이 백틱 유형 코드(`why`·`correction`·`constraint`·`context`)임
- **하위 불릿**: `source:`(사실을 정한 문서·이슈 또는 `사용자 확인 YYYY-MM-DD`)와 `evidence:`(코드 경로)만 허용하며, 근거가 코드 관찰뿐이면 `source:`는 생략함
- **금지**: 유형별 헤딩, 굵은 라벨, frontmatter, 타임스탬프
- **문장**: 적용 범위(제품·환경·코드 경로)를 문장 안에 밝힌 자기완결적 평서문으로 지금 참인 상태만 적음

## 갱신 규칙

- **덧붙이기**: 앞선 항목은 고치거나 지우지 않고 파일 끝에 덧붙이며, 틀려진 사실은 `correction` 항목으로 바로잡음
- **시점**: 사실이 드러나는 즉시 적고 늦어도 그 사실을 쓰는 커밋에 함께 담음
- **최종 확인**: PR 생성이나 머지 준비 선언 전에 브랜치를 한 번 훑어 빠진 항목을 보충하고 그 커밋을 남김

## 템플릿

```
# {slug} 작업 기록

- `context` {확인된 작업 의도. 사용자 문장 그대로.}
  - source: 사용자 확인 2026-09-14
- `constraint` {자기완결적 평서문 사실. 적용 범위를 문장 안에 밝힘.}
  - evidence: {코드 경로}
- `why` {선택과 기각한 대안, 트레이드오프}
```
