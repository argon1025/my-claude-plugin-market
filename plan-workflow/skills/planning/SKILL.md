먼저 [실행 환경 연결](../../references/runtime.md)을 읽고 패키지 경로·질문·위임 도구를 확정합니다.

근거 확인 → 항목별 인터뷰 → 합의 완료 확인 → 계획 작성 → 승인·인계 순서로 진행합니다. 기록 위치·slug는 세션의 작업 기록 규약과 `## 현재 워크스페이스` 블록을 따릅니다.

## 1. 목적과 작업 경계

- **목적**: 사용자가 원하는 결과를 함께 명확히 하고, 대화 기록이 없는 실행 에이전트도 구현할 수 있는 계획을 만듦
- **추정 금지**: 요구사항의 빈틈을 관행·기본값·추천안으로 채우지 않음. 제안은 사용자 동의 전까지 계획의 전제가 아니며, 명시적으로 위임받은 판단만 그 범위 안에서 대신 결정함
- **요청 범위**: 검토만 요청받으면 검토 결과만 제공하고 기록·커밋·구현 절차를 시작하지 않음. 계획 수립에서는 구현하지 않으며, 사용자가 세션에서 명시한 범위와 지시가 이 스킬의 기본 절차보다 우선함

## 2. 현황 조사와 의도 확인

- **선행 확인**: 관련 이슈·코드·세션에 주입된 문서 목록·작업 기록을 읽고 검증 가능한 주장을 확인함. 광범위 탐색은 읽기 전용 탐색 서브에이전트에 위임할 수 있으며, 직접 확인할 수 있는 사실을 사용자에게 대신 조사하도록 묻지 않음
- **의도**: 왜(현재 부족한 점)·누가 언제 겪는지·무엇이 참이면 끝인지를 파악함. 사용자가 이미 명시한 내용은 유지하고, 근거가 없는 항목만 하나씩 질문해 확정한 뒤 설계로 넘어감
- **요청 해석**: 해법형 요청은 해결하려는 문제를 먼저 확인함. `정리`·`개선`처럼 결과가 불분명한 표현과 범위·소유권에 대한 암묵 가정을 질문으로 바꾸고, 거짓 전제는 근거로 바로잡음

| 구분 | 취급 |
| --- | --- |
| 확인된 사실 | 코드·문서로 확인한 현재 상태. 출처를 기록하되 앞으로 유지할 동작이라는 합의로 간주하지 않음 |
| 확정 요구사항 | 사용자가 명시하거나 확인한 결과·정책. 기존 합의도 적용 범위와 근거를 확인해 유지함 |
| 제안 | 에이전트의 추천. 동의 전까지 미확정이며 문서에 있다는 이유만으로 승인된 것으로 취급하지 않음 |
| 위임된 판단 | 사용자가 항목·범위·제약을 정해 판단을 맡긴 것. 에이전트의 선택과 사용자 직접 결정을 구분함 |

## 3. 인터뷰 반복

1. **항목 선택**: 작업 결과를 달라지게 할 미결정 사항 하나를 고름. 목적·범위·구조처럼 후속 선택을 가르는 결정을 먼저 다루고, 앞 답에 따라 필요 여부나 선택지가 달라지는 질문은 뒤로 미룸
2. **설명과 질문**: 현재 상태, 결정 이유, 실제 동작 예시, 가능한 대안·트레이드오프와 추천 근거를 설명함. 구조·계약을 결정할 때는 바뀌는 파일·위치와 결과 형태(폴더 트리·시그니처 등, 질문 도구가 미리보기를 지원하면 함께 사용)도 제시함. 기존 팀 결정과 충돌하면 드러내고, 선택지 밖 사용자 대안도 받음
3. **답변 확인**: 한 번에 하나의 결정만 질문하고 답을 받은 뒤 진행함. 질문 도구에도 질문 하나만 넣고, 독립적인 결정을 한 질문에 묶지 않음. 아래 표는 답 전체의 의미로 적용하며, `모르겠으니 네가 결정해`처럼 명시적 위임이 있는 답을 단어만 보고 분류하지 않음. 모호한 답은 같은 항목의 의미를 더 확인함
4. **합의 갱신**: 답에 따라 결론과 남은 질문을 갱신함. 결정이 바뀌면 이전 결론을 대체한 이유와 영향을 받는 계약·정책·검증을 점검하고, 모순이 생긴 항목부터 다시 질문함

| 답변 | 처리 |
| --- | --- |
| `동의`·명확한 선택 | 바로 앞에서 제시한 결정에만 적용. 다른 요구사항·최종 계획·구현의 승인으로 확대하지 않음 |
| `모르겠어요`·이해가 어렵다는 답 | 설명·예시를 보충하고 다시 질문. 추천안 승인이나 판단 위임으로 간주하지 않음 |
| `알아서 결정해` | 대상이 명확하면 해당 항목에 한정한 위임으로 기록하고 범위 안에서 선택. 범위가 모호할 때만 확인하며, 위임 범위를 넘어서는 결정은 별도로 질문 |
| `일단 그 정도?`·잠정적 동의 | 미완성 목록이나 유보인지 확인하고 확정 전까지 미결정으로 유지 |
| 답변 없음 | 미결정 유지. 시간이 지났다는 이유로 추천안을 채택하지 않음 |

**합의 목록**에는 주제·현재 결론·근거와 확정/제안/미결정/위임/철회 구분을 유지합니다. 바뀐 결정은 대체 관계를 남기고, 새 근거가 없는 확정 사항을 반복해서 묻지 않습니다. 진행 중 목록은 세션·플랜 모드 초안에서 관리하고, 확정된 결정·변경 이유·위임 범위는 [기록 형식](../../references/record-format.md)에 따라 `feedback.md`에 남깁니다. 미승인 초안을 승인 스냅샷인 `plan.md`에 저장하지 않습니다.

## 4. 결정 누락 점검과 최소 코드 원칙

다음 축에서 이번 작업에 필요한 결정을 찾습니다. 이미 명시되거나 합의한 사항은 재질문하지 않으며, 가상의 미래 기능을 추가하거나 질문 수 자체를 늘리지 않습니다.

- **범위·사용 흐름**: 포함·제외, 누가 어떤 순서로 사용하고 어떤 결과를 얻는지
- **구조·영향 범위**: 새 코드의 소유 모듈·폴더, 기존 구조의 유지·재편, 호출자와 공유 지점. 기존 코드가 있다는 사실만으로 유지하기로 결정하지 않음
- **용어·도메인**: 사용자 용어와 코드 어휘, 객체·상태·허용값. 페이로드 필드·사용자 노출 문구·설정 키는 합의하거나 명시적 위임을 받으며 임의로 창작하지 않음
- **규칙·제약**: 조건과 결과, 상태 전이, 예외·오류, 저장·삭제·참조, 성능 등 비기능 요구
- **외부 계약·호환성**: 외부에서 참조하는 이름·키·코드와 변경·이전 정책
- **검증·완료**: 태스크별 실제 검증 명령, 기대 동작·출력과 통과 조건. 확인하지 못한 명령이나 결과를 만들어내지 않음

대안을 준비할 때 신규·수정 코드 모두에 **최소 코드 사다리**를 적용합니다.

- **첫 성립 단**: ① 만들 필요 없음 ② 코드베이스에 이미 있음 ③ 표준 라이브러리 ④ 플랫폼 기본 기능 ⑤ 설치된 의존성 ⑥ 한 줄 ⑦ 동작하는 최소 코드 순으로 검토해 첫 번째로 성립하는 단에서 멈춤. ⑦이면 앞선 단이 성립하지 않는 이유를 계획에 한 문장으로 적음
- **기존 코드**: 유지·수정과 재편·삭제를 변경 후 유지할 코드 양으로 비교하고, 재편 쪽이 적으면 지울 범위와 함께 후보로 올림. 사다리는 제안의 근거이며 사용자 합의를 대신하지 않음
- **금지·안전선**: 요청 없는 추상화·보일러플레이트·피할 수 있는 의존성을 추가하지 않음. 신뢰 경계 입력 검증, 데이터 손실 방지, 보안, 명시된 요구사항은 축소하지 않음
- **의도적 단순화**: 알려진 한계와 업그레이드 조건을 설명해 합의하고, 계획과 `feedback.md`의 `context` 항목에 남김

## 5. 합의 완료 조건

- **미결정 해소**: 범위 안에서 구현 결과를 달라지게 할 항목이 모두 합의되었거나 명시적으로 위임됨. 위임은 판단 범위·지켜야 할 조건이 명확해야 하며 `구현하면서 적당히 결정`으로 빈틈을 숨기지 않음
- **원본 대조**: 결정 간 모순·누락·철회된 제안의 잔존을 점검함. 세션에 주입된 `feedback.md`는 최근 일부일 수 있으므로 관련 원본 기록과 기존 계획을 읽고 최신 합의를 확인함
- **전환 확인**: 최종 합의·위임 범위·제외 범위를 요약해 사용자에게 확인받은 뒤 계획을 작성함. 새로운 결정을 요약 속에 끼워 넣지 않으며, 이미 받은 명시적 최종 확인은 반복해서 요구하지 않음

## 6. 계획 작성과 대조

- **자기완결**: [계획 형식](../../references/plan-format.md)을 읽고, 다른 에이전트가 대화 없이 실행할 수 있도록 확정 요구사항·현재 코드 근거·변경 범위·순서·검증·완료 기준을 작성함
- **결정 구분**: 사용자 직접 결정과 위임에 따른 에이전트 선택을 구분함. 실행자에게 남기는 재량은 범위·제약·검증 조건을 명시하며, 본문 전체를 합의 목록과 대조함
- **인터뷰 복귀**: 작성 중 새 결정·모순을 발견하면 해당 항목으로 돌아가 질문함. 계획의 빈칸을 추정으로 채우거나 미결정 상태에서 최종 승인을 요청하지 않음

## 7. 승인·인계

- **승인 구분**: 개별 질문에 대한 동의와 합의 요약 확인은 최종 계획 승인과 다름. 완성된 계획을 제시해 승인받은 뒤에만 아래 스냅샷 절차를 실행함
- **slug**: 세션 워크스페이스 블록의 slug를 쓰고, 미확정이면 작업 주제로 정해 사용자에게 알림
- **기존 계획**: `plan.md`가 있으면 추가 모드를 알림. 무관한 다른 주제이면 덧붙이지 않고 충돌을 보고한 뒤 정지함
- **추가·폐기**: 추가 모드는 `## 추가 계획 YYYY-MM-DD — {한 줄 계기}`를 끝에 덧붙이고 앞 절은 수정·삭제하지 않음. 무효가 된 결정은 추가 절 첫 불릿에 `폐기: {절 이름 또는 항목}`과 근거·대체 결정을 적음
- **스냅샷**: 승인된 계획을 신규 파일 또는 추가 절로 기록하고, 확인된 의도·결정 이유·위임·정정을 `feedback.md`에 반영해 두 파일을 한 커밋으로 남김
- **종료**: 새 세션에서 이 플러그인의 execute 스킬로 시작하도록 안내하고 턴을 끝냄. 계획 승인만으로 구현하지 않으며, 사용자가 별도로 지정한 기록·커밋·실행 범위는 그 지시를 따름
