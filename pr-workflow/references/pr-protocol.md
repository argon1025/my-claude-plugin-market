# PR 공통 규약

세 스킬이 첫 단계에서 좌표를 확정하고, 외부 쓰기 전에 승인 게이트를 거치는 절차입니다.

## 사전 조건

- **저장소 체크아웃**: `git rev-parse --show-toplevel`이 실패하면 시작하지 않고 중단함
- **PR 호스트 도구**: `git remote -v`의 URL로 호스트를 판별하고, 세션에 있는 도구 중 `gh` CLI(GitHub), `glab` CLI(GitLab), PR 호스트 MCP 도구(GitHub·GitLab·Bitbucket 등) 순으로 사용함
- **도구 부재**: 해당 호스트를 다루는 도구가 없으면 시작하지 않고 그 사실을 보고함. 도구 이름을 추측해 호출하지 않음

## 1. 저장소 좌표

- **원본 저장소**: `origin` URL에서 호스트·owner·repo를 읽음. `upstream` 리모트가 있으면 `origin`은 개인 fork이고 PR 대상은 `upstream`임
- **베이스 브랜치**: 사용자가 지정하지 않으면 저장소 기본 브랜치(도구 조회 또는 `git symbolic-ref refs/remotes/origin/HEAD`)를 사용함
- **확정 불가**: 어느 쪽으로도 확정하지 못하면 추측하지 않고 사용자에게 물음

## 2. PR 번호

- **URL 인자**: PR 번호를 추출하고 호스트·owner·repo가 1절 좌표와 일치하는지 대조함. 다르면 다른 저장소의 PR이므로 그 저장소의 체크아웃에서 다시 실행하도록 안내하고 중단함
- **숫자 인자**: 해당 PR의 제목·작성자·소스 브랜치를 보여주고 확인받음
- **인자 없음**: OPEN 상태 PR 목록을 아래 표로 보여주고 사용자의 선택을 기다림. 1건뿐이어도 단정하지 않음

| 번호 | 제목 | 작성자 | 소스 브랜치 |
|---|---|---|---|

## 3. 승인 게이트

코멘트 수정·삭제와 PR 본문 편집을 지원하지 않는 호스트가 있으므로 외부 쓰기는 편도로 간주하고, 승인 게이트를 유일한 방어선으로 둡니다.

- **1라운드 1승인**: 한 스킬의 한 라운드에서 바깥으로 나가는 행동을 한 묶음으로 모아 한 번만 물음. 행동별로 나눠 묻지 않음
- **승인 전 허용**: `git fetch`만 허용함
- **거절 시**: 아무것도 나가지 않고 로컬 상태만 보고함
- **후속 작업**: 승인 뒤 생긴 새 작업은 다음 라운드로 넘기고, 통과한 묶음에 끼워 넣지 않음

| 스킬 | 승인 범위 |
|---|---|
| create | push와 PR 생성 |
| review | 인라인 코멘트·재리뷰 답글·요약 코멘트 게시 |
| fix | 판정 세트 승인(커밋 전) / push와 스레드별 답글 |

## 4. 금지 행동

- **PR 승인·거절**: approve·decline·merge 계열 도구를 호출하지 않음. 보고서의 `권장:` 줄은 의견이고 승인 버튼은 사람 몫임
- **force-push**: 어떤 경우에도 하지 않음
- **실패 후 push**: 검증이 실패하면 push하지 않고 재시도 루프나 우회 없이 중단해 보고함
- **머지·거절 PR**: 사용자가 명시적으로 요청할 때만 코멘트를 남김

## 5. 보고 필수 항목

- **스킵 파일**: 리뷰하지 않고 건너뛴 파일과 사유
- **diff 절단**: 잘린 diff와 보지 못한 파일
- **앵커 강등**: 앵커 미확정으로 파일 레벨로 내린 코멘트
- **반증 제외**: 반증 패스가 떨어뜨린 건수
- **중복 제외**: 기존 코멘트와 중복이라 게시하지 않은 건수
- **기각 지적**: 기각한 지적과 근거
- **미실행 검증**: 돌리지 못한 검증 명령

## 6. 오류 처리

- **원문 보고**: 도구·인증·PR 조회 오류는 원문 그대로 보고하고 중단함
- **재시도 금지**: 좌표나 파라미터를 바꿔가며 다시 시도하지 않음. 앵커 지정이 API 오류로 실패한 경우에만 앵커 없이 1회 재시도하고 그 사실을 보고함
