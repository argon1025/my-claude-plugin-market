# PR 호스트 절차

`pr-protocol.md`와 세 스킬이 장 번호로 참조하는 PR 호스트 절차입니다. 승인 게이트·금지 행동·보고·오류 처리 같은 호스트 무관 규약은 `pr-protocol.md`를 따릅니다.

## 1. 도구

- **호스트 판별**: `git remote -v`의 URL로 호스트를 판별하고, 세션에 있는 도구 중 `gh` CLI(GitHub), `glab` CLI(GitLab), PR 호스트 MCP 도구(GitHub·GitLab·Bitbucket 등) 순으로 사용함
- **도구 부재**: 해당 호스트를 다루는 도구가 없으면 시작하지 않고 그 사실을 보고함. 도구 이름을 추측해 호출하지 않음

## 2. 저장소 좌표·베이스

- **원본 저장소**: `origin` URL에서 호스트·owner·repo를 읽음. `upstream` 리모트가 있으면 `origin`은 개인 fork이고 PR 대상은 `upstream`임
- **결과**: 원본 저장소의 owner·repo 한 쌍
- **베이스 브랜치**: 사용자가 지정하지 않으면 원본 저장소의 기본 브랜치(도구 조회 또는 `git symbolic-ref refs/remotes/origin/HEAD`)를 사용함
- **존재 확인**: create는 호스트 도구 또는 `git ls-remote --heads <원본 리모트> <베이스>`로 베이스 브랜치가 원본 저장소에 있는지 확인함

## 3. PR 조회

- **목록**: 호스트 도구로 원본 저장소의 OPEN 상태 PR(번호·제목·작성자·소스 브랜치)을 조회함
- **단건**: 호스트 도구로 PR의 소스·베이스 브랜치, 상태, 인라인·최상위 코멘트를 조회함

## 4. diff 조달

- **로컬 diff**: `git fetch <remote> <source-branch>` 후 `REVIEW_SHA=FETCH_HEAD`, `BASE`는 페치한 베이스 브랜치와의 merge-base
- **폴백**: 페치 실패, MERGED, DECLINED는 호스트 도구의 PR diff를 사용함

## 5. 저장소 관례

- **리뷰어**: 사용자가 지정한 경우에만 지정하며, 지정이 없으면 리뷰어 없이 진행함
- **PR 제목**: 브랜치명에 티켓 ID가 없으면 저장소의 기존 PR 제목 관례를 따름
- **리뷰 제외 경로**: 없음

## 6. push·생성·확인

- **push**: 소스 브랜치를 보유한 리모트(fork면 `origin`)로 `git push -u <remote> <branch>`
- **push 거부**: 원문을 보고하고 중단함
- **생성**: 호스트 도구로 PR 생성. 대상 저장소는 2장의 원본 저장소, 베이스는 확정한 베이스 브랜치, draft는 요청 시에만
- **확인**: 생성된 PR을 도구로 다시 조회해 베이스·소스 브랜치·리뷰어를 확인하고 PR URL을 보고함

## 7. 코멘트 게시

- **인라인 앵커**: 호스트 도구의 인라인 코멘트 파라미터로 새 파일 기준 라인을 지정함
- **답글**: 원 코멘트 스레드에 답글(reply) 형태로 붙임
- **게시 후 수정**: 코멘트 수정·삭제, PR 본문 편집, 스레드 resolve를 지원하지 않는 호스트가 있으므로 게시한 것은 고칠 수 없는 것으로 간주함
