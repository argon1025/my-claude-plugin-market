# 코멘트 형식 규격

`review`와 `fix` 사이의 상태는 전부 PR 코멘트에 있으며, 아래 접두사는 기존 PR 코멘트와의 호환 계약이므로 변경하지 않습니다.

## 1. 발견 코멘트 (`review` 인라인 게시)

```
<등급 이모지> **[AI 리뷰 · <구분>/<등급>]**

**<title — 결론 1문장>**
<fix — 행동 지시 1문장>

> <impact — 영향·근거 1–2줄>
```

- **등급 이모지**: 🚨 Blocker, 🐛 Bug, 💡 개선. 접힌 스레드 목록에서 등급을 식별하는 양식의 고정 요소이므로 작성 규약의 이모지 금지 예외임
- **suggestion_code**: 코멘트에 넣지 않음. 코멘트 수정·삭제가 불가한 호스트에서 틀린 코드가 스레드에 남음
- **앵커**: 호스트 도구의 인라인 코멘트 파라미터로 새 파일 기준 라인을 지정하며 추가·수정된 라인에만 닮. 확정하지 못하면 파일 레벨 코멘트로 내리고 본문에 `anchor 미확정`을 적음

## 2. 요약 코멘트 (`review` 파일 레벨 게시)

```
[AI 코드리뷰]
리뷰 스냅샷: <REVIEW_SHA> · 베이스: <BASE_SHA>
리뷰 범위: 파일 <N>건 · 스킵 <M>건 · 반증 제외 <K>건 · 중복 <D>건

<사람이 읽는 요약과 권장 1줄>
```

- **재리뷰 입력**: 두 번째 줄의 SHA가 다음 실행의 델타 스코핑 입력임
- **유효 상태**: 생성 시각이 가장 늦은 `[AI 코드리뷰]` 코멘트가 유효 상태임. 사람이 지우면 델타 스코핑을 포기하고 전체를 다시 봄

## 3. 반영 답글 (`fix` 스레드별 게시)

```
[AI 반영 · 수용] 반영했습니다 — <commit sha>
[AI 반영 · 기각] <근거 1~2줄>
[AI 반영 · 이미 해결] <확인 1줄>
```

답글은 원 코멘트 스레드에 답글(reply) 형태로 붙입니다.

## 4. 스킬 간 코멘트 판별 규칙

- **재리뷰 판별**: `review`는 `[AI 리뷰`로 시작하는 코멘트를 자기 출력으로 인식하며, 하나라도 있으면 재리뷰임
- **요약 제외**: `fix`는 미해결 스레드를 모을 때 앵커 없는 `[AI 코드리뷰]` 요약을 제외함
- **처리 완료 제외**: `fix`는 `[AI 반영`이 달린 스레드를 처리된 것으로 보고 제외함. 스레드 resolve를 지원하지 않는 호스트에서는 이 접두사가 유일한 판별 장치임
- **작성자 무차별**: `fix`는 사람 코멘트와 AI 코멘트를 똑같이 다룸. 접두사는 중복 판정용이지 우선순위가 아님
