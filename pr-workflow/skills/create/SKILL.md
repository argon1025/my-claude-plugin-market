현재 피처 브랜치로 저장소 기본 브랜치(또는 사용자가 지정한 베이스)를 대상으로 PR을 만듭니다.

## 계약 로드

- `${CLAUDE_PLUGIN_ROOT}/references/pr-protocol.md` — 사전 조건, 저장소 좌표, 승인 게이트, 금지 행동

## 가드레일

- **배경 창작 금지**: 브랜치가 담지 않은 PR 맥락을 만들어 내지 않음. 커밋 로그를 산문으로 옮긴 것은 배경이 아님
- **베이스 고정**: 베이스 브랜치를 조용히 바꾸지 않음. 다른 베이스가 필요하면 사용자에게 먼저 확인함
- **승인 전 외부 쓰기 금지**: 6절 승인 전에는 push도 PR 생성도 하지 않음. PR 본문을 편집할 수 없는 호스트가 있으므로 초안은 생성 전에 검토받음

## 1. 브랜치 맥락 수집

```
git branch --show-current
git remote -v
git log --oneline <base>..HEAD
git diff --name-status <base>...HEAD
```

- **코드 변경**: 리뷰어가 볼 대상. 코드 경로는 전체 diff를 읽음
- **기록 문서**: 브랜치가 커밋한 설계·결정 기록 md가 있으면 배경의 출처로 읽되, 작업 내역의 파일 목록에서는 제외함

## 2. 배경 게이트

다른 절을 쓰기 전에 `## 개요`의 `배경` 불릿을 지금 채울 수 있는지 먼저 판정합니다. 초안 문장에서 "무엇을 바꿨는지"를 지우고 남는 것이 없으면 배경이 없는 것입니다.

- **배경 아님**: `결제 모듈에 재시도 로직을 추가함` — 작업 내역의 재서술
- **배경**: `게이트웨이 타임아웃에서 주문이 유실되던 것을 막기 위함` — diff에서 얻을 수 없는 정보
- **통과**: 3절로 진행
- **실패**: 다른 절을 쓰지 않고 즉시 질문함. 열린 질문 하나만 던지지 않고 브랜치명의 티켓 ID, 커밋 메시지의 증상, diff가 만지는 영역이 시사하는 문제로 후보를 만들어 고르거나 고치게 함
- **확보 불가**: 사용자가 배경을 제시하지 못하면 PR을 만들지 않고 중단함. 사용자가 배경 없이 진행하라고 명시한 경우에만 `## 개요` 절을 통째로 생략하고, 생략 사실과 지시를 보고에 남김. 어느 경우에도 커밋 로그 요약으로 그 절을 채우지 않음

## 3. 리뷰어

사용자가 지정한 경우에만 리뷰어를 지정합니다. 추측하지 않습니다.

## 4. 제목·본문 초안

초안만 작성하며, 이 시점에 밖으로 나가는 것은 없습니다.

- **제목**: `[<TICKET>] <사실 요약>`. 브랜치명이 티켓 ID면 그것을 쓰고, 없으면 저장소의 기존 PR 제목 관례를 따름
- **문체**: 이 스킬은 절 구성과 절별 정보량만 정함. 문장 종결은 세션에 작성 규약이 주입돼 있으면 그것을 따르고, 없으면 불릿을 명사형으로 종결함

```markdown
## 개요
- **배경**: <이 변경 없이는 무엇이 안 되거나 잘못되는지. 한 문장>
- **변경**: <그래서 무엇을 했는지, 결론만. 한 문장>

## 작업 내역
- **<파일명·영역>**: <바뀐 결과의 나열. 한 줄>

## 영향도
- **<영향 대상>**: <바뀐 사실 한 구>로 <달라지는 동작 한 구>. <병합 전 확인이 필요하면 별도 문장으로>

## 검증 결과
- **<검증명>**: <결과. 한 줄, 수치는 괄호 부기>
```

### 절별 정보량

- **개요**: 배경·변경 고정 2불릿, 각 한 문장. 파일명·메커니즘·동작 방식은 아래 절의 몫
- **작업 내역**: 파일 또는 영역당 1불릿. 라벨은 경로가 아닌 파일명·영역명(동명 파일이 둘일 때만 경로). 추가·삭제·교체·개명 같은 바뀐 결과만 나열하고, 설계 의도·호출 관계·동작 원리는 적지 않음
- **영향도**: 변경 사실, 도달 대상과 달라지는 동작, 병합 전 확인(필요할 때만 별도 문장)의 3요소를 각 한 구로 담음. 앞 두 요소를 채울 수 없으면 영향 항목이 아님
- **검증 결과**: 검증 하나에 한 줄. 상위 명령(`npm run verify` 등)이 포함하는 검사는 다시 나열하지 않고 수치만 괄호에 부기함. 실행하지 않은 검증은 결과가 아니므로 병합에 필요하면 영향도의 확인 항목으로, 아니면 6절 보고로 보냄
- **출처 우선순위**: 검증 결과는 기록 문서의 결과가 있으면 그것을, 없으면 저장소 검증 명령을 직접 실행한 결과를 쓰고, 실행한 것이 없으면 절을 생략함

### 영향도 도출 4축

- **계약 변경**: 삭제·변경된 필드, 시그니처, 엔드포인트, 이벤트 payload. 저장소 내 grep으로 소비처를 확정할 수 없으면 확인 항목으로 남김
- **분기·조건 로직**: 판정 결과가 달라지는 변경. 뒤집히는 조건과 이전 판정을 명시함
- **데이터**: 마이그레이션, 컬럼, 인덱스, 시드. 도달 대상은 기존 행
- **설정·플래그**: env 키, 설정값, 기본값 변경. 도달 대상은 그 값을 읽는 환경

### 영향도 3규칙

- **영향 없음**: 4축 어디에도 걸리지 않으면 `- 기존 동작에 영향 없음` 한 줄만 적음. 비어 있어도 남는 유일한 절임
- **미확정 단언 금지**: 확정하지 못한 것은 확인 대상을 지목한 확인 항목으로 넘김. `영향 있을 수 있음` 단독은 항목이 아님
- **사실 기반**: diff의 사실에서 출발하지 않는 일반 리스크·성능 예측은 적지 않음

### 중복·분량

- **중복 금지**: 같은 사실을 두 절에 적지 않음. 같은 파일이 작업 내역과 영향도에 함께 나오는 것은 허용되나 같은 문장은 중복임. 절을 지워도 정보가 줄지 않으면 그 절이 중복임
- **상한**: 작업 내역·영향도·검증 결과는 각 4불릿 이하. 초과 시 영역으로 묶고, 묶어도 초과하면 PR 분할 여부를 사용자에게 물음

### 본문 제외 항목

- **루틴 명령**: 빌드·설치 명령을 실행했다는 사실. 리뷰어가 재현해야 하는 명령만 예외
- **무관한 기존 실패**: 이 PR과 무관한 기존 실패의 원인 분석. 베이스에서도 실패한다는 한 줄이 한계
- **diff 자명 사실**: 필드 순서, import 변경, 중첩 클래스 추가처럼 diff를 열면 보이는 것
- **대안 비교·일반 지식**: 기각한 대안과의 비교, 일반 기술 설명
- **불변 확인**: 바뀌지 않은 계약의 호환성 언급과 건드리지 않은 속성이 그대로라는 안심 문장
- **기록 문서**: `## 작업 내역` 파일 목록에서 기록 문서 제외

## 5. 승인 1회

대상 좌표, `from → to`, 리뷰어, 제목, 본문 전문을 보여주고 `pr-protocol.md`의 게이트로 한 번 묻습니다. 2절에서 배경을 사용자에게 받았으면 개요가 그 답변에서 나왔음을 밝힙니다.

## 6. push·생성·확인

- **push**: 소스 브랜치를 보유한 리모트(fork면 `origin`)로 `git push -u <remote> <branch>`. 거부되면 원문을 보고하고 중단함
- **생성**: 호스트 도구로 PR 생성. 대상 저장소는 1절의 원본 저장소, 베이스는 확정한 베이스 브랜치, draft는 요청 시에만
- **확인**: 생성된 PR을 도구로 다시 조회해 베이스·소스 브랜치·리뷰어를 확인하고 PR URL을 보고함
- **거절 시**: 아무것도 push되지 않고 PR도 없음을 그대로 보고함
- **핸드오프**: 마지막 한 줄 `리뷰: /pr-workflow:review 실행`
