# 위키 문서 규약

문서 한 장의 규격과 사실 하나의 판정 기준입니다. 기계가 볼 항목(frontmatter 키·날짜 형식·`description` 길이·경로 규칙·파일명·첫 줄 제목·`description` 중복)은 `scripts/catalog.py --check`가 검사하며 그 에러 메시지가 정본이고, 아래는 사람과 에이전트가 판단할 것만 적습니다.

## 1. 담는 것

- **grep 테스트**: 불릿 하나가 코드 검색 한 번으로 참이 확인되면 담지 않음 — 판정 단위는 문서가 아니라 불릿
- **제외 판정선**: 한 심볼의 정의로 환원되는 것(타입·시그니처·enum·파일 위치·호출 관계), 식별자의 내부 동작 서술, 이번 변경의 서사("A에서 B로 바꿈")는 제외
- **담는 것**: 코드 밖 맥락(도메인 정책·외부 서비스 제약·계정·인프라), 트레이드오프가 있던 결정과 버린 대안, 금지와 함정, 코드에 없는 컨벤션, 반복 절차, 소비처가 이 레포 밖인 외부 계약, 개인 개발 환경의 도구·경로·함정(공통)
- **담지 않는 것**: 코드·다른 시스템에 원본이 있는 사실, 모델이 아는 일반 지식, 미확정 계획·할 일, 린터·CI가 이미 막는 규칙(도구 위치 한 줄과 우회·예외만), 비밀값
- **자료 필터**: 기획서·설명서의 화면 시안, UI 문구 원문, 일정·담당자, "검토 중" 미확정 항목 제외

## 2. 문서 단위와 description

- **트리거**: 요약이 아니라 "어떤 작업을 할 때 열어야 하는지" 한 문장 — 40자 목표·60자 상한, "때" 종결, 이 문서에서만 참인 낱말 1개 이상 (좋음: `상품 상태를 바꾸거나 상태별 노출 조건을 다룰 때`)
- **한 주제**: 40자 한 문장으로 전체가 덮이지 않으면 분할 — 범주어로 올려 여러 주제를 한 문장에 넣는 것 금지, 각 40줄 미만·같은 주제·항상 함께 읽히면 병합
- **범위 낱말**: 도메인 루트 문서가 일부 레포에서만 참이면 `## 적용 대상`에 레포를 밝히고, 레포 문서는 폴더가 레포를 말하므로 description에 레포명을 넣지 않음
- **역커버리지**: 제목·description이 약속한 범위를 본문이 덮지 못하면 제목과 description을 본문 범위로 좁히고 채울 사실 없는 절은 두지 않음

## 3. 위치와 이름

- **위치 판정**: 이 레포를 지워도 참이면 도메인 루트 `knowledge/{조직}-{도메인}/`, 아니면 레포 폴더 `knowledge/{조직}-{도메인}/{레포 slug}/` — 한 단계 판정만 하며 한 사실이 두 성격이면 둘로 나눔
- **폴더**: 도메인 루트와 레포 폴더 2층 고정, 각 층은 평면이고 `adr/`만 하위 폴더 — 되돌리기 어렵고, 근거를 의심할 만하며, 실제로 버린 대안이 있는 결정 셋을 모두 충족할 때만. 회사 전체 공통 폴더는 두지 않고 레포는 한 도메인에만 속함
- **예약 파일**: 도메인 루트의 `index.md`는 도메인 지도로 예약되어 필수이며 레포 폴더에는 두지 않음 — 규격은 9장
- **파일명**: kebab-case 2~5단어 명사구, `adr/NNNN-slug.md`는 그 폴더 최대 번호 +1

## 4. 문서 모양

- **frontmatter**: `description`·`updated`·`verified` 3키만, 날짜 `YYYY-MM-DD`, 본문 첫 줄 `# 제목`
- **updated·verified**: updated는 고친 날, verified는 현실과 맞는지 확인한 날 — 대조 없이 verified 갱신 금지
- **권장 골격**: 규칙 문서 `## 적용 대상`·`## 규칙`·`## 예외`, 절차 문서 `## 트리거`·`## 단계`·`## 분기와 실패`, 용어 문서 `## 용어`·`## 상태와 전이`·`## 코드값`, `adr/` `## 컨텍스트`·`## 결정`·`## Why`·`## Apply when` — 내용에 맞지 않으면 변경 가능(`adr/` 제외)
- **절 응집**: 한 절은 제목이 답하는 질문의 사실만, 같은 주장 둘은 하나로 — 값이 다르면 통합하지 않고 충돌로 보고
- **출처 줄**: 본문 맨 아래 `> 출처: {종류} — {식별자}, {날짜}` — 종류는 `확인`과 `관찰`(`{slug} @{sha7} 머지`) 2종, 원본이 다르면 줄을 더하고 같은 레포의 `관찰` 줄은 최신 하나만 남김
- **확인 식별자**: 그 값을 정한 자료·판본 또는 결정을 짚음(`2026-03 약관 개정`, `개인정보 처리방침 v3`) — 근거를 댈 수 없는 값에만 `사용자 확인`을 쓰고, 값이 무엇에서 무엇으로 왜 바뀌었는지는 문서가 아니라 커밋 메시지에 둠

문서 한 장의 최소 형태입니다.

```markdown
---
description: 연체 회원의 대출 가능 여부를 판단할 때
updated: 2026-09-14
verified: 2026-09-14
---

# 연체 시 대출 제한

## 적용 대상

- 대출 신청 심사와 연장 심사 두 경로
- 법인 회원은 제외 — 여신 심사가 따로 있음

## 규칙

- 연체 30일 초과 시 신규 대출 차단 — 금융사 공통 여신 기준
- 연체 해소 후 90일간 한도 50% 적용

> 출처: 확인 — 2026-03 여신 기준 개정, 2026-09-14
```

## 5. 본문 문체

- **어미**: 음·함·됨·명사구 종결, 합니다체 금지 (`개발자 등급 변경 시 기존 약관 동의 무효화`)
- **불릿 단위**: 사실 하나 — 150자를 넘으면 둘 이상이거나 표 한 행
- **인과**: `규칙 — 근거` 꼬리, "~때문에 ~한다" 순서 금지
- **업무 낱말 우선**: 식별자는 업무 낱말 뒤 괄호 병기 `국외 이전 여부(isTransferCrossBorder)`, 식별자로 시작하는 불릿 금지, 코드 블록·따옴표 문구·표는 원형 유지
- **모호 표현 금지**: 적절히·필요시·일부 경우는 조건과 수치로 교체, 미확정은 "아직 정해지지 않음"으로 명시

## 6. 겹치는 사실

- **참조 금지**: 다른 위키 문서 링크·이름 표기·`참고` 절 금지 — 목록이 매 세션 주입되어 참조가 탐색에 기여하지 않음. `index.md`의 역인덱스와 `deps.json`의 간선은 레포를 가리키는 지도라 면제
- **접점**: 다른 주제와 맞닿아 없으면 틀린 결론에 이르는 사실만 문서 이름 없이 한 문장으로, 값 목록·표는 소유 문서에만
- **도메인 루트 우선**: 도메인 루트가 정한 값·목록은 레포 문서에 복제하지 않음

## 7. 사실 판정

- **대조**: 사실마다 목록 `description` 전수와 `grep -ril '{핵심어}' {WIKI_ROOT}/knowledge/{domain}`로 대상 문서를 찾고, 값 단위로 `동일`(verified만 갱신)·`보강`(추가, updated 갱신)·`충돌`(값 다름 또는 기존 문장이 거짓) 중 하나로 판정
- **종류가 가르는 것**: 새 사실 추가는 두 종류 모두, 기존 값 교체는 `확인`만 — 코드는 "지금 도는 것"만 답하고 "그렇게 하기로 했는지"는 답하지 않음
- **근거 판정**: 기존 값을 덮는 사실은 그 값을 뒤집은 근거를 요구함 — `개정`(정해진 것이 바뀜)·`재논의`(다시 정함)·`정정`(처음부터 틀림) 중 하나가 입력에서 읽히면 근거 있음, 새 값이 맞다는 주장만 있으면 근거 없음
- **충돌 처리**: 근거 있는 교체는 묻지 않고 반영하며 그 근거를 `확인` 식별자로 기록, 근거 없는 교체는 기존 값·기존 출처·새 값을 병기해 무엇이 그 값을 뒤집었는지 묻고 답에서 근거가 나오면 반영·나오지 않으면 기존 값을 유지한 채 `inbox.md`에 기재, 무인 실행은 물을 곳이 없어 항상 기재
- **inbox 행**: `- [{날짜}] [{domain}] {주제} — 기존 {값} ({파일:절}, {출처}) / 새 {값} ({근거} 또는 {slug} @{sha7} {code})` — 훅이 `- [`로 시작하는 줄을 세므로 형식을 지킴
- **병합 방식**: 기존 본문을 유지하고 해당 값만 고침 — 문서 전체 재작성·변경 서사 금지, 뜻이 달라지면 `description`도 다시 씀
- **되돌리기 어려운 편집**: 문서 삭제·분할·폴더 이동·`adr/` 신설은 사실 편입과 별개로 사용자 승인 필요

## 8. 반영

- **검사 후 커밋**: `catalog.py --check` 에러 0 상태에서 문서마다 `docs({domain}): {도메인 루트 기준 상대경로} {요약}` 커밋, `--no-verify` 금지
- **교체 사유**: 기존 값을 덮은 커밋은 본문에 `기존 {값} / 새 {값} — {근거}` 한 줄을 둠 — 개정 이력의 정본은 git history이고 문서 본문에는 현재 값만 남김
- **동기화**: 스킬 시작에 `git pull --ff-only`, 끝에 `git pull --rebase && git push` — 충돌은 멈추고 보고
- **입력 밖 금지**: 확정된 입력(자료·대화·diff) 밖의 사실을 사전 지식으로 채우지 않음

## 9. index.md

도메인 루트의 예약 문서로 "코드를 바꿀 때 어느 레포를 확인해야 하는가"에 답하는 지도입니다. 훅이 본문 전체를 세션에 주입하므로 아래 템플릿의 절만 두고, 사실 불릿은 담지 않습니다.

- **절 고정**: `## 레포 구성`·`## 역인덱스`·`## 접근 좌표`·`## 제외 레포` 4개만 — `접근 좌표`·`제외 레포`는 내용이 있을 때만 두고 절 추가 금지
- **사실 금지**: 반영 순서 계약·정책·함정 같은 사실 불릿은 도메인 루트 일반 문서로 두고 역인덱스가 그 레포 집합을 가리킴 — 토큰 상한은 두지 않으며 크기는 절 고정으로 다룸
- **도메인 밖 참조**: 역인덱스는 다른 도메인 레포를 `{domain}/{slug}` 꼴로 적을 수 있음 — 레포 간 의존은 10장 `deps.json`에 두며 index.md에 적지 않음
- **면제**: 2장 한 주제, 6장 참조 금지, 2장 범위 낱말 규칙에서 면제 — `description`은 고정문
- **정본 분리**: 기본 브랜치·remote는 `registry.json`이 정본이라 표에 두지 않음
- **작성 주체**: register가 골격(제목·한 줄 설명·레포 구성 1행)을 만들고 레포 추가·도메인 이동 시 행을 옮김, update가 `관찰` 출처로 소관·접점·역인덱스를 보강, add가 `확인` 출처로 접근 좌표·역인덱스를 보강
- **접근 좌표**: 좌표 1건당 1불릿, 비밀값 금지, 호출 예시는 코드 블록

```markdown
---
description: {도메인} 레포 소관·역인덱스·변경 파급을 볼 때
updated: YYYY-MM-DD
verified: YYYY-MM-DD
---
```

## 10. deps.json

레포 사이의 의존 간선을 담는 위키 루트 파일(`registry.json`의 형제)로, "이 레포를 바꾸면 어느 레포가 영향을 받는가"에 답합니다. 훅이 현재 도메인에 닿는 간선을 세션에 주입하고 `index.md`는 간선을 적지 않습니다.

```json
{
  "edges": [
    {
      "from": "onestore-display/display-front",
      "to": "onestore-devcenter/devcenter-api",
      "note": "상품 조회 REST",
      "source": "관찰 — display-front @a1b2c3d 머지, 2026-09-15"
    }
  ]
}
```

- **방향**: `from`이 `to`를 호출·참조함 — `to`를 바꾸면 `from`이 파급 대상
- **키**: `from`·`to`·`source` 필수, `note` 선택, 그 밖의 키 금지 — `from`·`to`는 `^[a-z0-9]+-[a-z0-9-]+/[a-z0-9-]+$` 꼴의 `{도메인}/{레포}`
- **source**: 4장 출처 줄과 같은 꼴 `확인 — {자료·결정}, {날짜}` 또는 `관찰 — {slug} @{sha7} 머지, {날짜}`
- **유일성**: `(from, to)` 쌍은 하나, 자기 간선 금지 — 같은 쌍을 다시 관찰하면 `source`만 최신으로 갱신하고 `확인` 간선의 `note`는 `관찰`이 바꾸지 못함
- **정렬**: `from`·`to` 사전순, 들여쓰기 2칸, 파일 끝 개행 — 병합 충돌을 줄이기 위함
- **부재**: 파일 없음은 간선 0건이며 에러가 아님
- **담는 기준**: 레포 사이의 호출·참조·소비 관계만 — 한 레포 안 모듈 의존은 담지 않으며, 지도이지 사실 문서가 아니라 1장 grep 테스트에서 면제
- **삭제**: 기존 간선 삭제·방향 변경은 기존 값 교체이므로 7장 근거 판정을 거친 `확인`만 가능(`add`·`audit`)
- **작성 주체**: update가 diff의 빌드 파일 모듈 의존·HTTP 클라이언트·메시지 발신·DB 공유에서 `관찰` 간선을 더하고, add가 자료·대화에서 `확인` 간선을 더하거나 지우며, register가 도메인 이동 시 끝점을 치환하고, audit이 index.md에 남은 옛 의존 절(9장 절 고정 밖)을 여기로 옮김
- **검사**: `catalog.py --check`가 키·형식·자기 간선·중복과 끝점의 `registry.json` 등록 여부를 봄
