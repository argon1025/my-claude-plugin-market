# 위키 문서 규약

위키는 "지금 무엇이 참인가"를 답하는 현행 합의이고, 도메인 루트 문서는 그 도메인의 MSA 레포들이 코드를 이렇게 구성한다는 합의입니다. 기계 검사 항목(frontmatter 키·`description` 길이·경로·파일명·첫 줄 제목·`description` 중복)은 `scripts/catalog.py --check` 에러가 정본이고, 아래는 기계가 가를 수 없는 것만 적습니다.

## 1. 담는 것

- **판정**: 레포(코드·설정·테스트)를 읽은 에이전트가 이 불릿 없이 같은 결론에 이르면 담지 않음 — 판정 단위는 불릿, 결정은 코드에 보이는 선택을 빼고 버린 대안·이유만 남김
- **담는 것**: 코드 밖 맥락(도메인 정책·외부 서비스 제약·계정·인프라), 한 레포만 읽어서는 드러나지 않는 레포 사이 맞출 값·방식, 버린 대안과 이유, 코드가 강제하지 않는 규칙·함정·반복 절차
- **담지 않는 것**: 지금 참이 아닌 것(변경 서사·미확정 계획), 외부 명세 전사(소재와 함정만), 일반 지식, 비밀값, 레포 소관·책임·의존(9·10장 그래프로)

## 2. 문서 단위와 description

- **트리거**: 요약이 아니라 "어떤 작업을 할 때 열어야 하는지" 한 문장 — 40자 목표, "때" 종결, 이 문서에서만 참인 낱말 1개 이상 (`상품 상태를 바꾸거나 상태별 노출 조건을 다룰 때`)
- **한 주제**: 40자 한 문장으로 덮이지 않으면 분할, 범주어로 여러 주제를 묶지 않음 — 각 40줄 미만·같은 주제·항상 함께 읽히면 병합
- **범위 낱말**: 도메인 루트 문서가 일부 레포에서만 참이면 `## 적용 대상`에 레포를 밝히고, 레포 문서 description에는 레포명을 넣지 않음
- **역커버리지**: 본문이 제목·description의 범위를 덮지 못하면 제목·description을 좁히고 빈 절은 두지 않음

## 3. 위치와 이름

- **위치 판정**: 이걸 모르고 개발하면 다른 레포에서 문제가 되면 도메인 루트 `knowledge/{조직}-{도메인}/`, 아니면 레포 폴더 `knowledge/{조직}-{도메인}/{레포 slug}/` — 레포 폴더는 그 레포 안에서만 관심 있는 세부(구성·함정·지켜야 할 방식, 예: JPA 구성)이고 설정값 전사 제외, 한 사실이 두 성격이면 둘로 나눔
- **폴더**: 도메인 루트와 레포 폴더 2층 고정, 각 층은 평면이고 하위 폴더는 `adr/`만 — 되돌리기 어렵고, 근거를 의심할 만하며, 버린 대안이 있는 결정 셋을 모두 충족할 때만
- **파일명**: 2~5단어 kebab-case 명사구, `adr/NNNN-slug.md`는 그 폴더 최대 번호 +1

## 4. 문서 모양

- **frontmatter**: `description`만
- **권장 골격**: 규칙 `## 적용 대상`·`## 규칙`·`## 예외`, 절차 `## 트리거`·`## 단계`·`## 분기와 실패`, 용어 `## 용어`·`## 상태와 전이`·`## 코드값`, `adr/` `## 컨텍스트`·`## 결정`·`## Why`·`## Apply when` — `adr/` 외에는 내용에 맞게 변경 가능
- **절 응집**: 한 절은 제목이 답하는 질문의 사실만, 같은 주장 둘은 하나로 — 값이 다르면 통합하지 않고 7장 판정

```markdown
---
description: 연체 회원의 대출 가능 여부를 판단할 때
---

# 연체 시 대출 제한

## 적용 대상

- 대출 신청 심사와 연장 심사 두 경로
- 법인 회원은 제외 — 여신 심사가 따로 있음

## 규칙

- 연체 30일 초과 시 신규 대출 차단 — 금융사 공통 여신 기준
- 연체 해소 후 90일간 한도 50% 적용
```

## 5. 본문 문체

- **어미**: 음·함·됨·명사구 종결, 합니다체 금지 (`개발자 등급 변경 시 기존 약관 동의 무효화`)
- **불릿 단위**: 사실 하나 — 150자를 넘으면 둘 이상이거나 표 한 행
- **인과**: `규칙 — 근거` 꼬리, "~때문에 ~한다" 순서 금지
- **업무 낱말 우선**: 식별자는 업무 낱말 뒤 괄호 병기 `국외 이전 여부(isTransferCrossBorder)`하되 업무 낱말이 없으면 원형만, 식별자로 시작하는 불릿 금지, 코드 블록·따옴표 문구·표는 원형 유지
- **모호 표현 금지**: 적절히·필요시·일부 경우는 조건과 수치로 교체, 미확정은 "아직 정해지지 않음"으로 명시

## 6. 겹치는 사실

- **참조 금지**: 다른 위키 문서 링크·이름 표기·`참고` 절 금지 — 목록이 매 세션 주입되어 참조가 탐색에 기여하지 않음
- **접점**: 다른 주제와 맞닿아 없으면 틀린 결론에 이르는 사실만 문서 이름 없이 한 문장으로, 값 목록·표는 소유 문서에만
- **도메인 루트 우선**: 도메인 루트가 정한 값·목록은 레포 문서에 복제하지 않음

## 7. 사실 판정

- **대조**: 사실마다 목록 `description` 전수와 `grep -ril '{핵심어}' {WIKI_ROOT}/knowledge/{domain}`로 대상 문서를 찾고 값 단위로 판정

| 판정 | 조건 | 본문 |
|---|---|---|
| `동일` | 기존 값과 같음 | 변경 없음 |
| `추가` | 기존에 없는 사실 | 추가 |
| `교체` | 기존 값과 다르고 교체 조건 충족 | 해당 값만 고침 |
| `건너뜀` | 기존 값과 다르고 교체 조건 미충족 | 변경 없음, 보고에만 |

- **교체 조건**: update는 그 값을 바꾼 의도를 밝힌 plan·feedback·커밋 메시지 인용(`quote`)이 있을 때, add는 사용자가 새 값을 고를 때, audit은 교체하지 않음 — 머지 시각은 적용 순서만 정하고 교체 여부를 정하지 않음
- **레포 편차**: 도메인 루트 값과 다른 레포 사실은 그 레포만의 사정이면(update는 `quote`로 가림) 도메인 루트를 유지하고 레포 폴더에 이유와 함께 `추가`하며 도메인 문서에 병기하지 않음(국가코드 `GA0000`을 프론트에서 `KR`·`EN`으로 표기), 합의 자체를 바꾸는 의도면 도메인 루트 `교체`
- **병합 방식**: 해당 값만 고치고 새 값으로 거짓이 된 다른 불릿은 같은 편집에서 삭제, 문서 전체 재작성 금지
- **description 유지**: `추가`는 바꾸지 않고, `교체`로 뜻이 달라질 때만 기존 트리거 낱말을 남겨 다시 씀
- **되돌리기 어려운 편집**: 문서 삭제·분할·폴더 이동·`adr/` 신설은 사용자 승인 필요

## 8. 반영

- **검사 후 커밋**: `catalog.py --check` 에러 0 상태에서 대상마다 아래 접두로 커밋

| 대상 | 커밋 |
|---|---|
| 문서 | `docs({domain}): {도메인 루트 기준 상대경로} {요약}` — 문서 한 장이 한 커밋 |
| 노드·간선(9·10장) | `docs(graph): {요약}` — `registry.json`·`deps.json`을 한 커밋에 담음 |
| 레포 등록·도메인 이동 | `chore(register): {slug} → {domain}` |

- **커밋 본문**: 발견 근거 한 줄(update `{slug} @{sha7}`, add 자료명 또는 `사용자 확인`, register `register 조사`)과 교체면 `기존 {값} / 새 {값}` 한 줄 — 이력의 정본은 git history이고 문서에는 현재 값만 남김
- **건너뜀 보고**: 반영하지 않은 사실은 스킬 최종 보고에 `| 주제 | 위치 | 기존 값 | 새 값·사유 |` 표로 남김 — 위치는 update `{slug} @{sha7}`, audit `{문서:절}`
- **편집 주체**: 노드·간선·커서는 아래 스킬만 고침

| 스킬 | 노드 | 간선 | 커서 |
|---|---|---|---|
| register | 전체(생성·재조사·도메인 이동·status) | 조사 간선 추가, 도메인 이동 시 끝점 치환 | — |
| add | `summary`·`project` 교체, `responsibilities`·`hosts` 보강 | 자료·대화의 간선 추가·삭제 | — |
| update | `responsibilities`·`hosts` 추가와 7장 조건의 교체 | diff의 간선 추가·`contracts` 식별자 보탬과 7장 조건의 교체 | `state/` 전진 |
| audit | 승인된 책임 문장 통합 | — | — |

## 9. registry.json — 레포 노드

"어느 레포가 그 업무를 맡는가"에 답하는 지도의 정본이며 세션의 레포 지도가 여기서 파생됩니다. 값 규칙(책임 문장·행위 낱말·호스트 리터럴)은 `graph.py schema --for facts`, 키·형식 검사는 `graph.py check` 출력이 정본이고, 아래는 스크립트에 없는 의미만 적습니다.

```json
{
  "domains": {
    "example-shop": {
      "description": "쇼핑몰 셀러 콘솔·주문 레포 모음",
      "repos": {
        "shop-api": {
          "project": "https://github.com/example-org",
          "remote": "github.com/example-org/shop-api",
          "defaultBranch": "main",
          "status": "active",
          "stack": ["Java 21", "Spring Boot 3.5", "JPA/QueryDSL", "AMQP"],
          "summary": "백엔드 API. 로그인 룰 체인·2FA·세션과 공지·메뉴·파일",
          "responsibilities": ["셀러 로그인 룰 체인 검증", "로그인 세션 발급·만료 관리", "알림 메시지 발행"],
          "hosts": {"prod": "api.shop.example.com", "qa": "qa-api.shop.example.com"}
        }
      }
    }
  }
}
```

- **중첩**: 노드는 소속 도메인 아래에 두고 `domain`을 따로 적지 않음 — 레포는 한 도메인에만 속하고 프로젝트 계층은 두지 않음
- **project**: owner URL — 도메인 머리글·접근 좌표의 owner와 clone 패턴(`{host}/{owner}/{slug}`)이 여기서 파생됨
- **status**: `dormant`는 update 대상에서 빠지고 지도에 `(휴면)`으로 이름만 실리되 지식 필드와 끝점 간선은 유지 — 휴면 레포도 소비처로 남을 수 있음
- **remote**: 정본 하나, 개인 포크 금지 — clone 패턴과 다를 때만 지도 행에 나감
- **defaultBranch**: update가 머지를 걷는 기준 브랜치
- **stack**: 주 언어·주 프레임워크만 버전(`Java 21`·`Spring Boot 3.5`), 나머지는 이름만(`MyBatis`·`AMQP`)
- **summary**: 소관 한 줄, 업무 낱말 우선
- **hosts**: 한 호스트에 여러 레포가 붙을 때만 경로 접두(`apps.example.com/admin`), 도메인이 없으면 IP

## 10. deps.json — 의존 간선

"이 레포를 바꾸면 어느 레포가 영향을 받는가"에 답하는 위키 루트 파일이며, 훅이 현재 레포 기준 선행 조건(나가는 간선)과 파급 대상(들어오는 간선)을 나눠 주입합니다.

```json
{
  "deps": {
    "example-shop/shop-api": [
      {
        "to": "example-shop/shop-notifier",
        "kind": "message",
        "contracts": ["shop.topic / seller-noti 발행 — 셀러 알림"]
      }
    ]
  }
}
```

- **그룹 맵**: `from`을 그룹 키로 모으고 항목에는 적지 않음 — 레포 하나를 갱신한 diff가 자기 블록에만 남아 동시 반영의 rebase가 충돌하지 않음
- **방향**: `from`이 `to`의 계약에 의존 — `to`를 바꾸면 `from`이 파급 대상, `kind`와 무관
- **메시지 방향**: 리스너를 가진 쪽이 `to`, 발행하는 쪽이 `from` — 발행/소비는 `contracts` 문장이 밝힘
- **대상 판정**: `to`는 식별자에서 읽히는 slug와 상대 레포 코드(`.local/paths.json` 경로, 없으면 `git clone --depth 1`) 확인으로 정함 — `library`·`http`·`data`는 artifactId·Feign `name`·호스트 앞머리의 이름으로, `message`는 같은 익스체인지·라우팅 키를 소비하는 레포를 `@RabbitListener`·바인딩으로 확인하고, `http`는 경로 접두가 상대 레포에 라우트로 실재하는지까지 봄
- **호스트 대조**: `~{host}`와 빈 대상은 scheme·끝 슬래시·대소문자를 지운 호스트를 registry `hosts` 전수와 비교해 slug로 바꿈
- **상대 미정**: 대상을 정하지 못했거나 registry 밖 외부 시스템이면 간선을 만들지 않고 `상대 미정`으로 보고 — 외부 시스템의 소재는 책임 문장이 짐
- **선언 위치**: `from`은 호출·발행·import 선언이 실제로 있는 레포 — 공용 라이브러리가 Feign을 선언하면 그 라이브러리가 `from`(http)이고 쓰는 레포는 `library` 간선만, 자체 선언이 있을 때만 직접 간선
- **경유 파생**: 주입·`repo`의 `이 레포에 의존`은 들어오는 간선의 `from`을 `library`로 쓰는 레포를 `(경유 {from})` 1홉으로 파생 — 저장하지 않고 계약도 싣지 않음
- **kind**: 필수 4값, 정의는 `graph.py schema --for facts` 출력 — 같은 두 레포가 `http`와 `message`로 함께 이어질 수 있음
- **contracts**: 한 줄이 `{식별자} — {왜 쓰는지}`, 의존당 3건 이내 — 넘으면 접두나 묶음(`cmsapp.cmsapp-agent.*`)으로 접음, 식별자 삭제·교체, 자유 텍스트 변경, 간선 삭제·방향 변경은 7장 교체 조건, Feign `name`·호스트·프로퍼티 키는 식별자가 아님, 형식 밖 줄은 `graph.py check` 경고

| kind | 형식 |
|---|---|
| library | `{group}:{artifact} — {왜}`, npm은 `{name} — {왜}` — 버전 접미는 빼고 |
| http | `{METHOD} {경로 접두}* — {왜}` |
| message | `{익스체인지} / {라우팅 키} 발행\|소비 — {왜}` |
| data | `{스키마}.{테이블 접두}* 조회 — {왜}` |

- **담는 기준**: 레포 사이의 의존만, 한 레포 안 모듈 의존 제외
