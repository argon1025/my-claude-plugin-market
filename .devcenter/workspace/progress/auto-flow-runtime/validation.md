# 합성 상점 배송비 검증

로컬 상점의 완료 조건은 조회 버튼을 누르면 해당 요청에서 API가 반환한 배송비가 화면에 표시되는 것이다. Codex CLI 0.171.0에 agent-wiki 0.15.0과 auto-flow 0.3.0을 설치하고 실행, 판정, 원인 조사를 별도 대화에서 직접 호출했다.

| 시나리오 | 앱 판본 | 조회 ID | 관찰 |
| --- | --- | --- | --- |
| API 단독 | `a4ef1f25` | `1888abfd-87ec-4350-8d5c-1d00bbf538f4` | 응답 2,500원 |
| 미리보기 | `a4ef1f25` | `e081e9e9-b7ef-42ed-ad68-2061cd031edc` | 대역 화면 2,500원, API 요청 0건 |
| 상점 화면 | `a4ef1f25` | `8ab8dd69-dac4-4943-a8a1-866158f10d59` | 같은 조회에서 응답 2,500원, 표시 2,000원 |
| 수정 후 상점 화면 | `52c85e47` | `05310845-f5fa-4d01-ac47-f5e176c8bc36` | 같은 조회에서 응답과 표시 모두 2,500원 |

1. API와 미리보기 결과만 받은 `review-goal`은 두 개별 조건을 충족으로 판정했다. 상점 화면 조건은 근거 부족으로 남기고 실행 담당에게 해당 화면의 조회를 넘겼다.
2. `run-scenario`가 실제 로컬 상점에서 응답과 표시를 함께 수집했다. 같은 조회에서 두 값이 달랐으므로 리뷰어는 화면 조건을 미충족으로 판정하고 해당 판본과 조회 ID를 조사 담당에게 전달했다.
3. `investigate-cause`는 화면 코드가 천 원 미만을 버리는 지점을 확인했다. 수정 후 같은 입력을 검증한 리뷰어는 상점 화면 조건을 충족으로 갱신하고, 변경 영향을 받지 않은 API와 미리보기에는 기존 근거를 적용했다.
