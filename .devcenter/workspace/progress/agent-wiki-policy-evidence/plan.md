# agent-wiki 작성·갱신 규약 개편

## 의도

정책 결정자와 레포 담당자가 같은 위키를 쓸 때 확정된 계약을 구현 전에 공유할 수 있어야 한다. 머지에서 수집한 동작이 정책을 덮어쓰는 일을 막고 두 스킬의 판정을 대표 사례로 확인한다.

## 확인한 사실

- 기존 references/doc-contract.md 1·2장은 경계를 넘는 코드 값을 도메인 공통 사실로 보며, 7장은 diff를 값 교체와 삭제 근거로 인정한다.
- skills/add/SKILL.md 4절은 자료로 이미 결정된 교체에도 확인을 요구한다. skills/update/SKILL.md 3·4절과 references/apply.md 3장은 머지 순서나 현재 코드로 결정을 뒤집을 수 있다.

## 합의

### 결정 근거에 따른 문서 선택과 반영

- 바꾸는 것 — add는 규격·결정의 적용 범위를 확인하고 확정된 값은 바로 반영한다. update는 머지에서 찾은 결정과 관찰을 구분한다.
- 모양 — 적용 대상이 분명한 필수 정책은 공통 문서에 출처와 함께 쓰고, 반복해서 필요한 코드 밖 지식은 프로젝트 폴더에 쓴다. 공통 정책은 프로젝트에서 링크로 참조한다.
- 이유 — AUTO-FLOW.md의 ‘기준이 되는 기록’과 1A에 따라 구현 변경만으로 보장을 바꾸지 않는다.
- 적용 범위 — 기존 agent-wiki의 문서 규약, 두 스킬, 공통 반영·검토 지침과 관련 사용 안내.

## 검증

가상 shop-api 저장소와 위키 두 사본에서 add의 입력 자료와 update의 머지 1건을 각각 추출·배정하고, 문서별 반영과 검토 결과를 대조했다. update 입력은 scripts/collect_update_merges.py로 수집했다.

| 가상 입력 | 두 스킬의 검토 후 결과 |
| --- | --- |
| 책임자가 주문 취소 API 허용 시간을 24시간에서 48시간으로 확정한 규격 v2 §1 | 재질문 없이 공통 cancel-window.md를 48시간으로 교체하고 출처를 남겼다. 실제 가상 API는 36시간 요청을 거부했다. 검토 결과에 정책 48시간과 구현 24시간의 차이가 1건 남았다. |
| 기존 판정식의 함수 분리 | 내부 함수 이름과 호출 순서는 어느 위키 문장에도 추가되지 않았다. |
| 코드에만 있는 어드민 목록 정렬 | 정렬되는 동작을 실행해 확인했고 위키 문서에는 추가되지 않았다. |
| 격리된 Jenkins 빌드 노드에 Node 20을 사전 설치해야 하는 제약 | 두 사본 모두 shop-api/jenkins-node.md에만 설치 조건과 이유를 기록했다. |

두 사본 모두 공통 문서 1장과 프로젝트 문서 1장이며 미결 충돌은 0건이었다. 로컬 저장소 테스트 14개(python3 -m unittest discover -s tests)와 Codex 로더 검사(python3 tests/check_codex.py)를 통과했다. 사례 검증 범위는 문서 검토까지이며 위키 PR 게시는 실행하지 않았다.

다음 세션에서 정책 분류와 근거 우선순위는 [문서 규약](../../../../agent-wiki/references/doc-contract.md), 문서 반영·검토는 [공통 반영 절차](../../../../agent-wiki/references/apply.md), 입력별 판정은 [add](../../../../agent-wiki/skills/add/SKILL.md)와 [update](../../../../agent-wiki/skills/update/SKILL.md)를 참조한다.

### gpt-6.2-sol 낮은 추론 설정 검증

구현 커밋 `047d5ee`로 독립된 dry-run을 세 번 실행했다. 실행마다 이전 대화·기대값 없이 시작했고, 추출·반영·검토 위임에도 같은 모델 설정을 사용했다. 패키지에서 가상 저장소를 가리키는 config.json만 바꿨다.

| 실행 | 입력 | 검토 후 문서와 보고 |
| --- | --- | --- |
| add | 감사 파일 조회 규격 제3판 §2, CI 러너 메모, 다운로드 함수와 관리자 목록 코드 | 공통 export-download.md의 7일을 21일로 교체하고 제3판을 인용했다. audit-api/runner-trust-store.md에 빌드마다 사내 CA를 등록하는 제약을 썼다. |
| update | 같은 자료와 코드가 포함된 가상 머지 8fdb94a | 같은 공통 문장을 반영했다. 빌드 제약은 audit-api/ci-build-ca.md에 썼다. 두 스킬 모두 함수 분리와 이름순 정렬은 기록하지 않았다. |
| update | 제2판을 그대로 둔 별도 가상 머지 c05943b. 다운로드 함수 분리와 관리자 이름순 정렬만 포함 | 사실·지도 후보 0건. 위키 작업 트리가 깨끗했고 7일 정책이 보존됐다. |

제3판을 받은 두 실행 모두 7일 초과 21일 이내에 규격은 HTTP 200을 보장하고 구현은 HTTP 410을 반환한다는 차이를 1건씩 보고했다. 가상 구현을 직접 호출해 7일 요청은 200, 8·14·21일 요청은 410임을 확인했다. 세 실행 모두 재승인 질문과 미결 충돌은 0건이었다. 검토 JSON, 실제 문서, PR 본문 초안과 Git 변경 경로를 대조했으며, 검증 범위는 로컬 dry-run까지다.
