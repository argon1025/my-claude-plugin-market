# agent-wiki 작성·갱신 규약 개편

## 의도

정책 결정자와 레포 담당자가 같은 위키를 쓸 때 확정된 계약을 구현 전에 공유할 수 있어야 한다. 머지에서 수집한 동작이 정책을 덮어쓰는 일을 막고 두 스킬의 판정을 대표 사례로 확인한다.

## 확인한 사실

- 기존 references/doc-contract.md 1·2장은 경계를 넘는 코드 값을 도메인 공통 사실로 보며, 7장은 diff를 값 교체와 삭제 근거로 인정한다.
- skills/add/SKILL.md 4절은 자료로 이미 결정된 교체에도 확인을 요구한다. skills/update/SKILL.md 3·4절과 references/apply.md 3장은 머지 순서나 현재 코드로 결정을 뒤집을 수 있다.

## 합의

### 결정 근거에 따른 문서 선택과 반영

- 바꾸는 것 — add는 규격·결정의 적용 범위를 확인하고 확정된 값은 바로 반영한다. update는 머지에서 찾은 결정과 관찰을 구분한다.
- 모양 — 적용 대상이 분명한 필수 정책은 공통 문서에 출처와 함께 쓰고, 반복해서 필요한 코드 밖 지식은 프로젝트 폴더에 쓴다. 공통 정책은 프로젝트에서 링크로 참조한다.
- 이유 — AUTO-FLOW.md의 ‘기준이 되는 기록’과 1A에 따라 구현 변경만으로 보장을 바꾸지 않는다.
- 적용 범위 — 기존 agent-wiki의 문서 규약, 두 스킬, 공통 반영·검토 지침과 관련 사용 안내.

## 검증

두 스킬에서 확정된 정책 변경, 정책을 유지한 리팩터링, 코드에만 있는 편의 기능을 대입해 문서 위치·내용·재질문 여부를 확인한다. 반복되는 레포별 빌드 제약도 확인한다. 저장소 테스트는 python3 -m unittest discover -s tests 로 실행한다.

## 범위 밖

실제 사내 위키 문서 정리는 세션 2에서 진행한다. 위키에 적용 상태나 별도 관리 절차를 추가하지 않는다.
