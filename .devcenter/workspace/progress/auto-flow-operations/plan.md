# Auto Flow 운영 스킬과 담당 인계

## 의도

문의 응대자와 개발 담당자는 앞선 대화를 몰라도 원래 요청·Jira·PR·배포·검증 기록에서 맡은 작업을 시작할 수 있어야 한다. 세션 4는 운영 책임을 구현하고 두 플러그인 설치 환경에서 담당 교체와 외부 쓰기 복구를 확인한다. 실제 적용은 사용자가 지정할 새 이슈에서 요청한 작업만 수행한다.

## 확인한 사실

기준 커밋 `c566c20`의 auto-flow 0.3.0에는 개발 경로 스킬 12개가 있다. 3B의 합성 상점 기록은 실행·목표 판정·원인 조사 간 인계를, 과거 이슈 재현 기록은 제품 코드·로컬 실행으로 입증한 부분과 웹 QA가 필요한 부분을 구분한다. 세션 3의 운영 명세는 `AUTO-FLOW-SPEC.md`의 AC-01~10, AC-23~28에 있다.

## 합의

### 접수부터 결과 안내까지의 독립 호출

- 바꾸는 것 — 문의 분류·일반 답변·Jira 연결·진행 조회·배정·질문·회신 인계, 병합 판정·실행, 배포 확인, 상태 전환, 안내 대상 조회·전송을 각각 호출한다.
- 모양 — 요청한 한 책임을 수행하고 대상의 위치·판본·근거·남은 일을 반환한다. 공통 스킬은 사내 운영 규칙과 도구를 환경 지침에서 찾는다.
- 이유 — 조회한 사람이 실행하거나 결과를 보내는 사람과 달라도 같은 원본에서 이어야 한다. 외부 응답이 끊기면 실제 목적지에서 누락을 확인한 쓰기만 재개한다.
- 적용 범위 — auto-flow 패키지와 마켓 정보, 두 플러그인의 설치·사용 안내, AC별 검증 기록.

## 검증

패키지 테스트와 `python3 tests/check_codex.py --auto-flow-only`를 실행한다. 로컬 모의 호스트에서 병합 응답 유실, VDI 대기 중 담당 변경, 새 머지가 없는 주기의 QA 가능 안내, 전송 단독 복구를 재현한다. 사람이 만든 원본으로 단독 호출하고, 후임에게 이전 대화 없이 호스트 위치를 넘긴다. 호출 결과와 외부 쓰기 수를 대조한다.

## 범위 밖

운영 이슈 임의 선정과 테스트용 실메시지는 제외한다. 새 이슈 키는 구현·모의 검증을 마친 뒤 요청한다.
