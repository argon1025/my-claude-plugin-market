# Auto Flow 운영 스킬 검증

Codex CLI 0.171.0의 임시 마켓과 설치 홈에 `agent-wiki 0.15.0`과 `auto-flow 0.4.0`만 설치했다. 로더에서 위키 스킬 4개, 업무 스킬 25개, 위키 시작 훅 1개를 확인했다. 담당자는 매 호출마다 새 대화에서 설치된 스킬을 읽었다. 이전 담당자의 대화 기록 없이 원래 문의·PR·이슈·배정처만 넘겼다. [설치와 전체 흐름](../../../../README.md)

**실제로 실행한 범위**는 Codex 설치·스킬 호출 46회와 로컬 호스트의 조회·쓰기다. **모의한 범위**는 Teams 메시지, Jira 이슈와 전환, PR·병합, Orca 수신함, VDI 회신과 Actions 배포 기록이다. 사람이 작성한 PR·질문·답변은 평가자가 만든 입력을 사용했다. 3B의 SQL 판정은 당시 반환 원문을 사용했다. 운영 이슈·대화에 접근하거나 실제 병합·배포·인계를 수행한 건수는 0건이다.

20개 모의 입력에서 매 호출이 요청한 쓰기의 종류·수신처·성공 여부를 호스트 로그와 대조했다. 호스트는 같은 메시지를 두 번 보내면 두 건 모두 저장한다. 아래 번호는 [실행 근거](evidence.json)의 `runs[].id` 앞 두 자리다. 각 항목에 요청·응답 원문, 새 세션 ID, 사용한 스킬 해시, 호스트 호출 순서가 있다. `cases`에는 각 사례의 초기 원본과 평가자가 주입한 회신·배포·장애가 있다.

초기 전송 실패 응답에는 “전송했습니다”와 “미확인”이 함께 있었다(11). 게시 위치를 확인한 때만 전송 완료로 보고하도록 `send-result`를 보완하고 두 장애를 다시 실행했다. 재실행에서 두 담당자는 응답이 끊긴 시점에 실제 게시 여부를 미확인으로 남겼다(37·39).

## 개발 경로와 실제 적용 범위

AC-11~20의 계획·개발·테스트·PR·리뷰 처리와 게시 복구는 [3A 검증 기록](../auto-flow-development/plan.md#검증)에 있다. 이번에는 AC-17 리뷰 단독 호출을 다시 실행했다. AC-21·22·29의 실행 증거, 독립 판정, 원인 조사와 수정본 검증은 [3B 상점 검증](../auto-flow-runtime/validation.md)에 있다. 이번 상태 갱신 검증은 3B의 기존 판정을 소비했다. 과거 QA 환경이나 제품을 다시 실행하지 않았다.

패키지 테스트 28개, 두 플러그인 로더 검사, 전체 로더 검사(스킬 34개·훅 4개), Claude 플러그인·마켓 매니페스트 검사가 통과했다. Claude 디렉터리 제출용 아이콘 경고가 있었으며 Claude 모델의 업무 실행은 검증하지 않았다. 운영 Teams 검색·전송, Jira 권한·전환 정책, 실제 Orca 수신·Bitbucket 병합·VDI·Actions 배포는 지정된 새 이슈에서 맡긴 범위만 확인할 항목으로 남는다.
