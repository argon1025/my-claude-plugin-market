# agent-wiki 정기 실행과 주제 점검

## 의도

위키 담당자가 서비스 머지를 기다리는 동안에도 확정된 정책과 기존 문서를 대조할 수 있게 한다. 서비스 변경 없이 빠진 계약, 미반영 결정, 일부만 고친 정책과 중복 문서를 실제 변경안에서 확인한다.

## 확인한 사실

- AUTO-FLOW.md가 연결한 AUTO-FLOW-SPEC.md의 AC-W1~W8과 1A의 문서 규약이 판정 기준이다.
- 기존 update는 collect_update_merges.py가 10을 반환하면 종료한다. apply.md는 문서별 반영과 독립 검토를, publish.md는 열린 PR 확인과 게시를 맡는다.
- 공통 플러그인의 기본 위키와 실제 개발자센터 위키는 원격과 PR 호스트가 다르다.

## 합의

### 기존 호출, 직접 점검과 정기 실행

- 바꾸는 것 — 지정 주제를 한 번 점검하거나 등록 도메인의 최근 변경과 제한된 범위의 코드·문서를 한 번에 검토한다.
- 모양 — 기존 머지 전용 호출을 보존한다. 정기 실행은 서비스 머지, 결정 변경, 위키 변경, 코드 순회와 문서 순회의 진행을 구분한다. 같은 대상·조건·주장·근거 판본의 검토는 공유한다. 문서만 점검할 때는 머지 커서를 유지한다.
- 이유 — 머지 수집만으로는 문서 없는 기존 기능이나 PM이 반영하지 않은 결정을 찾을 수 없다. 기존 문서·지도 반영 절차와 원격 PR 경로를 재사용한다.
- 적용 범위 — agent-wiki update와 검증 자료. 첫 직접 점검은 사내 개발자센터 2차 인증이며 필요한 수정은 사내 위키에 PR로 제안한다.

## 검증

- 실제 Git 모의 입력 네 사례의 문서와 변경 내역, 유지할 예외·링크·제약을 확인한다.
- 같은 입력에서 개별 수집과 통합 dry-run의 문서·근거·검토·호출·시간과 측정할 수 있는 토큰을 비교한다. 조회 실패, 열린 PR과 반영 후 재실행, 두 회차의 독립 순회와 문서 점검 시 머지 커서를 확인한다.
- 결정 원문에서 인증번호와 임시 세션의 유효시간을 따로 확인한다. 저장소 검증은 python3 -m unittest discover -s tests 및 python3 tests/check_codex.py로 수행한다.

검증 결과와 운영 분량은 [개별·통합 dry-run 비교](comparison.md)에 기록했다. 저장소 테스트 23개를 통과했고 패키지 로더에서 스킬 12개와 훅 4개를 확인했다.
